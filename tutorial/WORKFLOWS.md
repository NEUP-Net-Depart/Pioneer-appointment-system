# 教程工作流与知识点归属

先按实际工作任务组织，再把小功能放进会用到它的环节。身份仅为部长、部员、维修事务；不按单个按钮设置课程，不用固定步数删减工作环节。

## 部长

### 考勤与值班核查

到站确认校区与班次 → 本人到岗签到 → 看到签到结果并返回工作台 → 展示签到二维码 → 值班人员扫码 → 进入今日值班核查到岗情况 → 查看签到来源 → 对照维修人员工作状态与接单量 → 核实漏签后补录 → 必要时修正到场时间 → 查询考勤历史 → 核对志愿计数与导出。

小功能归属：个人首次签到、二维码有效期和更新、应到/实到/请假、签到来源、空闲/维修中、接单量与志愿时长的区别、补录原因、日期与月份筛选、历史下钻、志愿表与周考勤导出。

### 预约与设备维修

查看预约记录并定位机主 → 返回今日工作 → 打开扫码 → 识别机主维修码 → 核对设备、故障和资料 → 查保修与官方支持 → 校对现场信息 → 记录设备正反面 → 接收并开始维修 → 排查与处理 → 必要时补充过程照片 → 选择实际处理结果并写明验证 → 结束工单 → 交付机主 → 遗失查询链接时核验并补发 → 查看原登记及维修交接记录。

小功能归属：记录筛选与搜索、工作人员签到码与机主维修码的区别、在保与液金等风险信息、照片预览/替换、资料编辑与未保存提醒、首次接收与补充照片的区别、仅接收与开始维修的区别、处理结果选项、更正结果、查询凭证交付、原始登记与操作追溯。

本流程不再讲本人签到和考勤导出，这些归考勤流程。维修期间保持同一工单，不通过预置“已接收/已完成”跳过步骤。

### 值班与业务配置

新成员建档 → 配置有效任职 → 本人提交申请后负责人核验激活 → 核对账号与重置密码 → 收集空闲并编排下周 → 核对建议并手动调整后发布 → 配置每周预约名额 → 复制、核对并保存 → 查看日期实际容量 → 设置维修地点 → 临时暂停及恢复服务 → 配置放号时间和公告。

小功能归属：人员与账号的区别、任职生效日期、激活核验、常规空闲与本周例外、自动建议与手动调整、草稿/核对/发布、容量模板与实际容量、复制范围、受影响预约、地点历史、暂停恢复、公告启停及放号。

这里只教部长拥有的业务管理功能，不加入主席团或系统管理员专有权限，不重复介绍考勤和设备维修。

## 部员

### 到岗与完整维修

确认校区与安排 → 在今日工作打开扫码 → 识别工作人员签到码 → 核对签到日期、校区与本人账号 → 确认签到 → 查看成功结果并返回工作台 → 查看预约工单 → 打开扫码并识别机主维修码 → 核对设备与故障 → 查询保修、校对现场资料 → 正反面照片 → 接收并开始维修 → 排查、补充记录 → 填写处理结果并结束 → 交还设备 → 查看本人工作与签到记录。

签到预览、确认和结果必须分别显示。设备从未接收开始；已有接收记录时，只需开始维修，不能把这个替代路径当成所有设备的默认状态。

维修功能使用与部长维修流程同一份定义，按权限省去管理记录。一个身份内只介绍一次保修、照片、查询链接等知识点，不再另开这些小功能的课程。

### 值班安排与变动

查看我的班次 → 填报通常空闲 → 设置单周例外 → 临时无法到岗时请假 → 恢复可到岗时撤回 → 邀请同事接替并等待回应 → 情况变化时撤回邀请 → 回应收到的邀请 → 核对最终班次。

小功能归属：整班空闲、例外覆盖、请假与接替的区别、邀请不是立即换班、撤回与回应。本人签到历史归完整维修流程，不在这里重复。

## 维修事务

### 到岗出码与人员协调

本人直接到岗签到 → 查看成功结果 → 展示工作人员签到码 → 核对今日到岗人员、空闲维修人员与接单量 → 为机主安排后续交接。

不教部长专用的来源审计、补录、历史导出；不把维修事务的直接签到与部员扫码签到混成一种操作。

### 接待与设备交接

查找预约 → 扫描机主维修码 → 当面核对机主、设备与故障 → 校对现场资料 → 上传正反面照片 → 仅接收设备 → 查看接收结果与待维修状态 → 交给有维修资格的同事；遇到无预约机主，再走现场登记 → 机主确认协议及签名 → 创建新工单 → 为新工单拍照接收 → 核对交接状态。

小功能归属：查询与扫码的不同入口、校对与原登记证据、接收照片、取消选图不退出工单、补充附件、查询链接补发、现场登记与协议签名。维修事务没有开始和完结维修权限，不在教程中伪造这些按钮。

## 组织与交互约束

- 每个身份下只显示上述完整工作流。功能说明随工作环节出现，不再额外列一套重复的功能介绍。
- 引导只用一句大字点出容易漏掉的入口、规则或后果，不显示解释段落。原因、普通字段与保存合并演示，不逐项教学。预约记录必须覆盖日期概览、状态直达筛选、搜索范围与清空恢复。
- 每步有明确的当前任务和结果；实际扫码窗口、签到确认、成功结果、接收照片、维修状态变化都必须展示，不能由一个辅助动作连续跳完。
- 引导推进统一使用“下一步”；只有当前步骤对应的操作会被执行。可随时退出后自由操作，不混入“继续/跳过/帮我演示/暂停”。
- 同一工单从打开到完结保持连续；现场登记后切换到刚创建的新工单。角色之间共用功能定义，按权限显示。
- 每项小功能有唯一知识点标识。同一身份的不同工作流不重复讲解同一知识点；必要的日常动作可以重复，但只描述当前任务。
- 手机端保留相同内容与操作顺序，重点检查扫码弹窗、确认按钮、签名、照片区域、较长表单、退出与下一步是否可见且可操作。重要内容不能依赖悬停。
- 示例中的空闲、维修中、漏签、请假、接单量和班次归属必须来自同一份业务记录。页面直接复用 dev 的原组件和样式，日期与校区按真实配置和权限展示。

## 验收

检查真实画面和业务结果，而不只核对按钮数量：签到确认前不能产生到岗记录；接收前不能已有原图；结束前必须实际开始过维修；事务人员不能成为主修；现场新单必须继续被处理。分别完成三个身份的所有工作流，并在手机宽度下完整重放。
