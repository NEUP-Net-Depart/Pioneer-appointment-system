# 人员平台升级候选

此目录用于隔离验证，不由 `db:migrate`、CI 或远端发布自动执行。正式切换前必须同步五状态业务代码、确定追加迁移的部署路径，并核对目标 D1 的实际迁移账本。

| 来源 | 候选脚本 | 目标 |
| --- | --- | --- |
| 已部署 Staff 0007 | `staff-0007-to-five-statuses.sql` | 保留成员、任职、角色、考勤、核验和维修占用，转换预约状态并增加 expires_at 与修正记录表 |
| dev 0009 | `dev-0009-to-staff-platform.sql` | 保留现有五状态、期限、修正记录及容量快照，追加人员平台及历史账号映射 |

来源 dev：`135da288204d20a9c06d9579d7bf61813b2587fc`。测试中保存的 0007～0009 历史 SQL 位于 `tests/fixtures/dev-migrations`，附原文指纹；0001～0006 与当前分支共用。已执行的迁移文件保持原样。

运行 `node --test tests/staff-upgrade.test.mjs` 验证：

- Staff 九种历史状态/结果组合的转换，原主键、私人凭证哈希和时间保持，expires_at 按原业务日期 21:30 上海时间回填。
- 两路径中途注入失败后数据完整回滚，再执行同一候选成功。
- Staff 的附件引用、存储额度、核验、恢复凭证、签到和容量快照保留；dev 的历史修正记录保留。
- 成员映射、维修占用互斥和释放后的新接单、附件删除额度触发器、外键完整性。
- 两路径最终表定义、索引、触发器、列和外键一致。

这些证据来自本地隔离 D1，不证明远端现有数据已升级，也不证明旧应用可直接运行于目标 schema。当前候选为一次性升级 SQL，正式迁移账本负责防止重复应用；不得绕过账本直接反复执行。
