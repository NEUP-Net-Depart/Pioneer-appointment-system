# 现场值班闭环验收（首个停止节点）

实施分支：`next/staff-platform`。本阶段覆盖接待、签到、核验接单、现场转派、维修完成与岗位联动；排班申请、成员管理体验及报表改版仍属于后续阶段。

## 本地启动与账号

运行 `npm run preview:field`，使用终端输出的 `/staff/` 地址。该命令创建一次性本地 D1/R2，离开进程后清除；不会写入线上数据库。样例仅在本地 `--serve --field` 中通过真实接口生成。

| 账号 | 人员 | 用途 |
| --- | --- | --- |
| `20261001` | 林悦 | 南湖校区办公接待 |
| `20261002` | 陈宇 | 维修员 A |
| `20261003` | 周宁 | 维修员 B |
| `20261004` | 许晨 | 维修值班负责人，兼维修员 |
| `root001` | 预览负责人 | 最高管理员 |

上述隔离预览账号密码均为 `StaffTest!2026`。真实部署不创建这些账号。预览签到场次采用全天窗口，业务默认窗口仍为 18:30–21:30；临时登记仍遵守当天业务截止时间。

## 操作路径

建议不同岗位使用独立浏览器会话，或退出后切换账号。

1. 林悦进入接待台，选择“展示签到码”。
2. 陈宇、周宁进入维修工作台，选择“到岗签到”。扫描签到码或保存二维码后从相册识别，核对校区、日期及窗口后确认。桌面测试可在各自会话从相册选择同一张签到二维码。
3. 林悦查看空闲人员，点击已有样例；也可用“临时登记”录入机主、设备并签名。详情展示维修码，登记不会占用维修员；关闭详情可继续登记。
4. 陈宇扫描维修码或输入完整单号，核验厂商、型号、保修和液金情况，上传设备正反面照片后确认开始维修。刷新或重新登录可继续当前维修。
5. 许晨切换“现场管理”，打开该工单，选择“转交其他维修人员”，选择空闲的周宁并填写原因。查看原维修员恢复空闲、接手人员显示当前维修。
6. 周宁填写维修说明、选择结果并确认提交；查看接待列表、当前任务和人员状态的变化。

操作成功后本页面立即更新；其他在线会话每 30 秒同步，也可点击“刷新”。隐藏标签页暂停轮询并中止进行中的查询，恢复可见后按数据新鲜度更新。摄像头需主动开启，关闭扫描、页面隐藏或离开页面时释放。

## 实现边界

- `STAFF_WORKFLOW_ENABLED=true` 开启新工作台；当前仅 Staff Staging 和隔离现场预览启用。其余部署沿用原入口。
- 使用共享五状态、权限计算、成员标识、二维码、附件和预约命令；核验信息独立保存，不覆盖机主原始答案。
- 新增迁移 `migrations/0012_field_workflow.sql` 与 Staff Staging 对应的 `database/staff-migrations/0010_field_workflow.sql`；旧迁移保持不变。
- 接单、转派、完成的业务更新、审计和回执在同一 D1 batch 中提交；签到记录、在岗事件与审计同批提交。并发采用版本与成员当前维修约束，重试复用操作编号。
- 工作台、旧列表、导出使用统一客户字段投影；当日岗位权限不用于读取其他日期的客户资料。历史进行中维修仍由本人继续处理。
- React/TypeScript/Vite 工作界面通过现有认证宿主接入。后续排班、成员和报表页面尚未全部迁移，不能据本节点宣称整个平台重构完成。

## 自动检查与人工范围

`npm run verify` 包括类型检查、架构审计、原有业务回归、两条迁移链、旧页面浏览器回归与现场闭环测试。

新增测试验证真实接口联动、连续登记、重复提交、审计失败回滚、离岗与接单竞争、并发接单和转派、跨日维修、字段范围、会话及权限撤销、草稿恢复、320/390/1440 px 布局、二维码生成、后台暂停刷新和模拟摄像头轨道释放。

自动浏览器检查使用 Chromium。iOS Safari、QQ/微信内置浏览器以及真实摄像头硬件需在设备上验收，不能由模拟轨道测试替代。
