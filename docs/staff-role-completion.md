# 岗位和授权验收

组织归属、工作岗位与管理权限分别保存。账号旧版角色不替代岗位资格，也不隐式扩大授权校区。完整发布门槛见 [集成验收指南](releases/staff-platform-review.md)。

| 身份 | 验收边界 | 自动化证据 |
| --- | --- | --- |
| 旧管理员 | 原密码和原校区管理功能直接可用；不强制办公归属，不升级 superadmin；跨校区管理被拒绝 | admin-cutover.test.mjs 双迁移链、cutover-release.test.mjs 快照演练 |
| 维修人员 | 显式岗位资格、有效授权及当天到岗决定接单；本人在修可跨日完成；其他成员客户资料不可读 | field-workflow.test.mjs、integration.test.mjs、field-flow.spec.mjs |
| 办公接待与负责人 | 明确授予岗位和范围；签到不增加原授权；办公权限不能替代维修资格 | staff-authz.test.mjs、field-workflow.test.mjs |
| 成员及授权管理人员 | 编辑资料与编辑授权分别校验；条件、范围、有效期完整保留；旧版本和撤权写入被拒绝 | staff-platform-http.test.mjs、staff-authorization.spec.mjs |
| 排班与考勤人员 | 校区和部门范围独立校验；历史事实保留，修正不改变实时到岗 | roster-workflow.test.mjs、roster-flow.spec.mjs、staff-duty-updates.spec.mjs |

## 校区需求与非排班到岗验收

1. 维修负责人进入“维修排班管理”，创建收集任务时选择校区、部门与排班周，填写四个工作日的普通人员最低人数。可以先整周设置，再单独改某日。
2. 为另一校区建立任务，设置不同人数；分别打开“维修人员需求”，确认两个校区的配置独立保存。只有需求配置权限的办公负责人可在此调整人数，不能因此编辑或发布维修班表。
3. 普通维修人员和负责人填报可用时间；交流人员不应出现填报或换班入口。自动生成后，每日分别显示负责人 1 人、普通人员至少 N 人。缺少负责人、低于 N 或普通人员尚未安排时不能发布，超过 N 可以发布。
4. 同时打开两份需求配置，先保存其中一份；另一份保存应提示版本冲突并保留输入。发布前若需求、资格、授权、可用时间或相关班次发生变化，应要求重新核对。
5. 没有当天排班的普通维修人员、负责人和交流人员分别扫描“工作人员签到码”。接待台应出现这些人员，并显示非排班到岗；具备接单资格者可接单，有效负责人可在授权校区现场协调。签到不会增加计划班表人数。
6. “考勤核查”按月份和校区查看记录。修正时间必须填写原因；重新提交同一请求只保存一次，旧版本修改被拒绝。历史补录与修正不会让成员成为今天可接单人员。
