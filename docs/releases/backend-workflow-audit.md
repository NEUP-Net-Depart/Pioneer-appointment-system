# 工作人员平台后端流程与安全验收

本次按值班日的实际操作核查人员平台：授权与激活、排班收集和发布、现场签到、接待登记、核验接单、转派、完成维修、请假换班、考勤及管理追溯。结论限于下列已执行的本地数据库和浏览器回归；远端部署结果以对应 CI 和 Staff Staging 冒烟为准。

## 岗位流程检查

| 岗位 | 操作路径 | 已验证的后端约束 |
| --- | --- | --- |
| 维修与交流人员 | 激活资格 → 签到 → 核验预约码或查单 → 接单 → 完成 → 查看本人记录 | 未排班也可签到；交流人员不进入排班；同一人只允许一个进行中维修；重复提交、并发接单、跨日工单和权限撤销有回归。 |
| 接待人员 | 开启签到展示 → 查找预约或登记临时客户 → 展示维修码 → 查看人员到岗与处理进度 | 工作人员签到码与客户维修码分开；接待范围受校区和对象权限限制；人员状态随签到、离岗及工单更新。 |
| 维修负责人 | 建立收集任务 → 查看填报 → 自动排班 → 调整与发布 → 现场转派与处理异常 | 负责人每日每校区一名、普通维修人数达到各校区当日下限；未排班负责人在授权校区签到后可处理现场任务，跨校区与过期授权仍拒绝。 |
| 办公负责人 | 收集可用时间 → 自动排班 → 调整发布 → 审批请假换班 → 考勤修正与导出 | 办公按周内次数均衡、每人每天最多一班；审批、班表、签到与修订使用版本和冲突检查。 |
| 最高管理员 | 导入与激活 → 维护成员任职、资格和角色 → 检查审计与统计 | 修改成员、任职、角色、账号和现场事实时，授权版本与审计跟随同一数据库事务；受限审计授权不能读取全局日志。 |

## 本轮发现并修复

- 旧接待汇总接口对历史日期和校区范围的检查弱于现场工作台。现在复用现场工作台的当日授权和数据投影，防止通过旧接口读取越权汇总。
- 跨来源的 `PUT` 写入此前没有进入来源检查；现在与其他写入方法一致。签到接口不再接受客户端自称的 NFC 或手工验证事实，真实 NFC 接入前只允许现有二维码流程。
- 签到展示和考勤操作此前可能用客户端提供的历史业务日期复活已过期的管理授权。管理授权现在按操作当日检查，记录日期仍按业务规则保存。
- 成员、任职、角色、账号、在岗状态和签到展示的部分写入此前会与审计分离。相关写入现在同事务提交；审计失败、旧版本或已撤销的写入者不会留下部分业务结果。账户审计不记录密码材料。
- 新版整周收集任务此前仍能被旧的单日填报接口修改；现在明确拒绝旧入口。自动延续提交还会在落库时核对偏好版本，关闭自动延续后不会被并发的延续解析写回；截止后的解析按截止时偏好历史处理。
- 200 人导入后的结果查询曾超过 D1 单条语句绑定参数限制；现按批读取并维持稳定顺序。
- 历史审计记录没有统一的校区、部门归属字段。受限审计授权现在拒绝全局日志查询，防止以校区参数伪装过滤；按范围查看审计仍需单独实现。

## 验证范围

自动化使用隔离的 Miniflare D1/R2 和浏览器实例，覆盖正常操作及审计写入失败、重复请求、并发开场、并发接单与转派、发布竞争、权限撤销、跨部门转移、历史日期、跨校区访问和大量名单导入。本轮分别执行并通过全部本地门禁：248 项 Node 测试、180 项通用浏览器测试、39 项工作人员浏览器测试，以及静态检查和两条迁移链验证。通用浏览器运行中另有 39 项工作人员场景按配置跳过，已由独立工作人员套件验证。隔离测试账号及样例不会进入部署数据。

## 发布前仍需处理的范围

- 循环收集已改为一次发布的持久任务：按日历解析工作周，不依赖后台调度。各周快照、偏好历史及请求回执防止历史覆盖和重复提交；负责人失效时需要有权限的负责人保存设置以接管。
- 校区或部门范围内的审计查询尚未提供完整的历史记录归属过滤；目前只允许拥有全局审计权限的账号读取日志。
- 规划中的数据管理“范围选择 → 数量预览 → 确认删除 → 结果回执”没有完整 API 与页面。维修、考勤和排班覆盖的综合统计及筛选也未全部接通。
- 真实 NFC 硬件和完整会议业务不在当前交付范围。上线前仍需用目标 Cloudflare 环境的迁移、部署与冒烟结果，以及实际岗位账号进行人工验收。
