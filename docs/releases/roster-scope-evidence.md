# 部门排班范围验证

排班任务按岗位、校区和部门区分。新增任务的校区与部门选项由服务端根据当前完整授权生成；管理任务必须覆盖任务声明的每一组校区、部门，不能拼接不同范围的授权。成员参加资格按具体班次日期的有效任职与工作资格判断，管理授权按当前日期判断。

- `tests/roster-scope.test.mjs`：范围交叉、授权有效期、周中转部门及本人读取。
- `tests/staff-platform-http.test.mjs`：真实 Worker/D1 的任务创建、邀请名单、列表投影、填报、撤权及越权任务编号。个人响应不返回邀请名单。
- `tests/e2e/roster-flow.spec.mjs`：部门负责人创建流程、禁止空部门提交、服务端范围选项及 320/390/1440px 布局；原换班、请假、办公排班与维修排班流程继续回归。
- `tests/roster-task-upgrade.test.mjs`：dev 0018 与 Staff Staging 0016 两条追加迁移，保留任务、级联填报、班表和申请引用；注入迁移失败后全部回滚，成功后外键完整。

迁移只修改任务唯一性为“周、时段、岗位、范围”，不重写历史任务范围；同一范围重复创建返回冲突提示。既有任务继续使用原校区范围，部门受限负责人不能管理包含范围外成员的旧任务。

本地检查：208 项 Node、53 项通用浏览器、27 项人员平台浏览器通过；通用套件中的 27 项人员平台用例按环境跳过，再由人员平台套件执行。lint、类型检查、架构审计、双配置迁移重复执行及外键检查通过。首次完整执行的草稿恢复用例依赖第一项任务，修正为明确打开被测任务后整组人员平台回归通过。

限制：本批不代表任务创建及生成草稿的审计、回执已经原子化；这两类命令仍需后续完善。任务目录的完整分页仍待补齐。部门范围验证也不能替代全部接口的多部门授权矩阵或实机验收。
