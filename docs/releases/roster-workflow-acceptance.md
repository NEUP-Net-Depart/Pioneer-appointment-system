# 排班收集与发布验收

本轮维修与办公共用“发布收集 → 整周填报 → 结束收集 → 自动排班 → 人工调整 → 检查发布 → 修订”流程。每日人数在收集任务内按日期、校区设置；维修为普通人员下限，另含恰好一名负责人；办公为目标人数，默认一人，优先均衡周内班次数，每人每天最多一班。

## 本地操作路径

运行 `npm run preview:field` 创建隔离 D1/R2，控制台显示当前地址。`root001` 和夹具账号 `20261001`～`20261004` 的本地密码为 `StaffTest!2026`。额外验收数据只写入本地临时库，不随部署发布。

1. 负责人进入值班管理的维修或办公排班管理，新建收集任务，选择校区、部门与成员，统一填写人数后逐日调整；如需长期收集，开启每周填报并设置开放和截止时间。
2. 成员进入“我的 → 班次与排班”提交整周可用时间，或明确选择整周无法参加。开启自动延续后，后续同岗位任务按星期、校区、时间提交，标明自动来源；手动提交不被覆盖。自动延续可单独关闭。
3. 负责人查看已提交／应提交、未填报名单和每日候选缺口。提前结束时核对未提交名单，结束后生成自动排班。
4. 从具体日期添加、移动、替换或移除人员。超出原填报时间需要明确确认，原填报保留；资格、授权、每周次数及其他班表冲突不能绕过。锁定仅作用于具体班次。
5. 保存校验，处理缺额和冲突，预览差异后发布。缺额只能保存草稿，不能发布。成员端应出现相同班次。
6. 点击“调整已发布班表”复制当前安排。发布修订前旧班表保持有效；已签到及过去班次保留。重新开放收集不会自动修改任何班表。

## 一次发布、按周填报

循环收集只发布一次，工作人员一直从同一个普通任务入口填写当前对应周。每周开放和截止时间按北京时间、值班前一周解释；不使用定时作业、后台补发或按周重复发布任务。管理端在同一任务中切换工作周，分别管理收集、草稿及已发布班表。

数据库中的周次记录仅用于保存各周事实，打开任务时按日历解析当前周；长期无人访问不会补建所有错过的周。未来设置变更不改写已经建立的周次、原填报和已发布班表。负责人停用或授权失效时，只提示该任务需要由有管理权限的负责人接管，不阻断其他收集任务。

自动延续以截止时有效的偏好为准。即使截止后才首次查看，也可恢复当时已启用的选择；截止后才开启的偏好不能回填过去。已有提交始终优先，普通手动迟交仍被拒绝。关闭个人自动延续不删除已有提交。

正式版的编号候选搜索已接入新维修工作台：两位及以上尾号仅查当天，含前段和短横线的编号可跨日期查找。搜索与详情复用同一对象权限判断，仅返回编号、校区、日期、时段和状态。
