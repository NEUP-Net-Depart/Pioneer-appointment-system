# 工作人员白名单与自主激活

管理员在账号管理中导入 CSV，再发统一网址 `/staff/?activate=1`。部员填写本人学号、姓名、所属校区、核验联系方式，并自行设置密码。角色与授权校区只来自管理员名单，申请表中的同名属性不能扩大权限。

CSV 表头必含 `studentId`，可选 `expectedName`、`expectedRole`、`authorizedCampuses`。角色只能为 technician/admin；多个校区用 `|` 分隔。缺少角色或授权列时使用导入表单中的默认设置。支持 UTF-8 BOM、CRLF 和标准 CSV 引号；单次最多 200 条，先完整验证再写入，重复学号和错误行使整批失败。已有资格或账号会跳过，不覆盖；撤销或恢复资格由列表显式操作。

管理员只能导入、审核和管理低于自身角色且完全处于自身授权校区内的资格。最高权限者可导入管理员；普通管理员只能导入维修人员。新增 superadmin 仅允许由受控初始化脚本处理。

待审申请没有正式账号，也没有可登录的基础角色。数据库唯一索引限制同一学号只有一条待审申请。管理员必须逐人核实身份，批量通过时勾选已核验并记录说明。拒绝保留审核记录、清除申请密码哈希，允许重新申请；撤销资格会同时拒绝待审申请。

一次通过审核的 UPDATE 触发 `activation_approve`，原子创建正式账号和校区授权、标记资格已激活，并清除申请中的密码哈希。并发审批通过 pending 状态及白名单 revision 防止重复账号或使用过期资格；任一创建失败回滚整个操作。D1 batch 的事务行为见 [Cloudflare 官方文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。

申请回执为随机凭证，浏览器保存；数据库只保存哈希。公开审核状态只接受 `X-Activation-Receipt`，不能凭学号读取申请资料。核验联系方式加密保存，只向具有管理权限的管理员展示。

无短信或邮件时不能仅凭学号确认身份。名册姓名可过滤误填，仍需人工核验。恶意抢占待审申请时，管理员应拒绝并让本人重申；不要依据白名单学号自动批准。回执遗失可联系管理员，审批通过后直接用本人设置的密码登录，不需要回执才能登录。
