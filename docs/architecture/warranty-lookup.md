# 设备保修查询

“今日工作”的维修人员入口支持手动输入、条码识别和设备标签 OCR。联想查询返回原厂服务明细；Acer、华为查询需要用户完成原厂人工验证。其他品牌提供固定的消费者自查入口及操作步骤，品牌配置集中在 `shared/warranty.js`。

原厂查无数据、验证码错误、格式改变、拒绝访问和超时均不能解释为过保。联想服务项目按原厂起止日期和中国标准时间计算，包含到期当日；附加服务不单独证明整机在保。Acer、华为保留原厂明细，整机状态为 unknown。查询结果只填写核验草稿，不自动提交接收或接单。

## 扫描与 OCR

ZXing 读取条码，Tesseract.js 与英文模型自托管，选择照片后才加载。照片与 OCR 原文只在浏览器内存处理，不上传预约后台或第三方 OCR 服务。OCR 识别 S/N、SN、Serial、Service Tag 等标签，由用户确认候选，不自动猜测相似字符，也不识别验证码。

OCR 图片上限 12 MB、4000 万像素，识别前缩小长边至 2200px，超时 60 秒；取消或关闭后终止 Worker。相机不可用时仍可手动输入或从相册导入。

用户核对可编辑序号后，点击「复制序列号」，再点击「打开品牌官网」进入固定原厂页面。两项操作与状态反馈位于查验步骤上方的同一操作区。支持预填的品牌会在原厂 URL 中带入序号，页面明确提示；链接不携带学生身份、预约编号或登录令牌。原厂页面在独立标签页打开。复制失败时提示人工复制或重试，不自动聚焦输入框；小程序渠道显示操作步骤。

## 接口与会话

- `GET /api/warranty/providers`：返回品牌模式与配置状态。
- `POST /api/warranty/challenge`：取得原厂人工挑战，JSON 上限 2 KiB。
- `POST /api/warranty/query`：提交序号、短期加密会话和人工答案或 proof，JSON 上限 24 KiB。

接口要求有效工作人员登录；challenge 与 query 共用每 IP 每分钟 10 次限额，外连超时 12 秒。上游地址固定，禁止跟随转址，不接受客户端指定 Cookie、URL 或请求头。

人工会话采用 AES-GCM 加密，绑定用途、品牌、工作人员、序号及 3 分钟有效期，只保存在弹窗内存中。Acer 保留原厂 ASP.NET 会话与同一会话的验证码图片；华为保留原厂选择的验证类型，proof 必须匹配服务端挑战。只提取允许的设备和服务字段，不向客户端返回整页 HTML、机主姓名或联系方式。

## 独立验证站点

华为官方组件在独立来源 iframe 中运行。主页面检查消息来源、iframe Window 与随机 nonce；iframe 不接收序号、登录令牌或加密的原厂会话。

验证站点位于 `warranty-verifier/`，部署配置见 [验证站点说明](../../warranty-verifier/README.md)。发布工具生成两个站点的 CSP，并统一构建和 Functions 运行期的 `WARRANTY_CAPTCHA_ORIGIN`。站点必须跨来源，配置缺失或不一致时停用人工验证。`npm run preview:local` 使用独立本地端口。

自动化验证使用模拟原厂响应、人工挑战与 SDK，真实运行本地 OCR 和验证站点 CSP，不向原厂提交虚构序号。手机相机、反光标签及原厂人工验证的完整查询仍需使用真实设备检验。
