# 签到策略与凭证

## 志愿时长导出

考勤记录页通过 `/api/attendance/matrix` 合并所选月的有效排班、请假与真实签到，按人员和校区汇总，避免未签到人员从历史中消失。相同人员同校区同日多个班次合并计数；全部班次请假不计应到；无应到班次的签到另记临时支援。当天最后一个未请假班次结束后仍未签到，自动记缺勤；此前显示待签到。补记后自动恢复已签到，不需人工确认或撤销缺勤。暂停日期保留明细但不计入出勤统计。所有事实先经过考勤导出权限过滤，签到来源只向具有对应人员考勤修正权限的查看者返回。

前端支持本地姓名、学号、部门搜索和状态筛选，展开人员查看逐日记录；进入当日考勤操作后，返回保留查询条件。人员按正式主部门分组排序，硬件部优先，其余部门按名称排列，无部门置后；历史月份取月末任职，当前月份取今日任职，无对应任职时使用签到部门快照。导出使用当前筛选人员，文件区分实际签到、请假、缺勤、待签到与暂停服务。补记沿用版本校验和审计，并失效历史统计缓存。

自动计入开关依据统计期间的有效任职，包含正副部长、正副站长、正副主席。系统管理员、维修事务、交流维修身份本身不触发自动计入；兼任上述职务时依有效任职计入。自动计入属于志愿核算，不生成实际签到。修改全局规则仍要求全部校区的 `settings.manage` 权限。

信息采集表采用用户提供的“南湖先锋信息采集表10月3周”版式，保留 A–J 列、合并表头、列宽和行高。仓库模板已清除样例名单及个人属性；导出按人员数量生成明细和打印范围，学号写为文本，避免前导零丢失。文件按校区和周分别打包。更换模板不改变既有周归属、计数或活动日期口径。

## 值班人员接单量

`GET /api/attendance/workload?campusId=...&businessDate=...` 与今日值班列表使用相同的考勤查看权限及人员范围，只返回该日班表与签到人员的 `memberId/monthly/total`，不接受客户端指定其他人员。计数跨校区，响应不包含工单或其他校区的客户资料。

接单量按人员与不同工单去重，从 `repairs.started` 和 `repairs.transferred` 审计取得实际接手事实。同单交回原人员不增加累计，也不把原接手月份改成再次交接月份。本月以北京时间当前自然月、该人员首次接手时间计算，历史值班日期只影响人员列表，不改变统计月份。接口返回 `month/asOf`。只接收设备、分派、签到、工单结果更正均不增加接单量。

无对应人员接手审计的旧工单，使用当前负责人和 `started_at` 补计，不排除已停用账号；已有接手审计优先于工单上保留的原开始时间。无法从现存数据恢复审计建立以前的全部交接人员，此补计不是对缺失历史的推断。

统计按当前列表批量聚合，复用现有成员审计索引与负责人索引，不增加计数表或 R2 读取。前端在人员列表显示后独立读取并缓存一分钟；接单、交接、手动刷新会更新计数。读数更新不改变人员行高，失败展示未取得值，不能当作零。

签到由 `attendance_events` 场次、`attendance_tokens` 可替换凭证和 `attendance_records` 成员事实组成。二维码格式为 `pioneer:attendance:v1:<token>`；服务端仅保存 token 摘要，登录会话确定成员身份。刷新凭证保留场次 ID，旧凭证立即失效。

## 策略契约

`AttendancePolicy` 提供以下方法，策略版本随场次和事实保存：

| 方法 | 职责 |
| --- | --- |
| `resolveSource` | 解析业务来源 |
| `checkEligibility` | 判断来源及参加资格 |
| `getDedupeScope` | 生成唯一事实范围 |
| `prepareEffects` | 返回同批业务效果计划 |
| `describeResult` | 描述签到结果 |

凭证摘要、成员身份、唯一事实及审计由 attendance 服务统一处理。值班去重键为 `duty:<memberId>:<businessDate>`，同步 `staff_presence`；会议场次使用 `meeting:<memberId>:<eventId>`，按场次参加名单校验，只维护该场次出勤事实。

## 修正与安全

公开签到只接受现有二维码及服务端认可的自行签到流程，不信任客户端自称的 NFC 或手工验证事实。管理补录保存原发生时间、实际录入时间、当时组织快照和审计原因，当前授权、目标场次及资料在同一 D1 batch 中断言。

历史补录和修正不改变实时在岗，登记请假不伪造实际签到。列表、导出与周核算先过滤授权范围，再聚合事实；暂停日期不允许值班签到或补录。业务规则见 [考勤与暂停日期](../requirements.md#排班与考勤)。

值班和补记直接读取新 duty_assignments 与 roster_leaves；普通维修权限不作为签到资格。管理范围按当前部长本校区、站长/主席全部校区判断。周/月报算法及小时参数不变，默认核算不写签到，主修工单数量和持续时间不参与出勤计算。

## 今日任务与核查

`GET /api/attendance/day?campusId&businessDate` 从有效班次关联请假和签到，按当前访问范围过滤后按成员去重。返回 `items/temporary/summary/people/serverNow` 及每人的可用操作。与历史统计共用自动缺勤判断；请假单列且排除应到，临时到场单列。旧 `pending` 汇总字段及 `canReview/canConfirm` 操作字段已移除。

“确认到场”代签到入口已停用；`POST /api/attendance/arrivals` 在认证后返回 410，其服务和数据库写入方法已删除。现场人员应通过本人扫码或本人具备权限的自行签到完成签到。漏签由有权限的管理人员填写原因后走补记流程，保留操作人、默认班次时间标记、版本校验与审计。历史到场确认记录不删除。

工作人员无需维护实时在岗状态，手动状态切换接口已移除。工作台按本人、业务日期和当前校区的真实 `attendance_records` 隐藏已完成的签到待办；不会用 `staff_presence` 或前端身份标签代替考勤事实。历史在岗表及签到事务中的到场审计仍保留，不迁移或清除历史数据。

`PUT /api/attendance/reviews` 已停用，在认证后返回 410。人工确认未到和撤销入口、内部服务、数据库写入及班次查询关联均已移除；旧核查表与审计仅保留历史，不再参与当前考勤状态计算。

志愿时长页按人员去重列出缺少学院或学号的记录。服务端按该人员当前所属校区与任职计算资料管理权限；有权限者可直接打开人员详情，保存后自动刷新志愿报表，无权限者显示联系人员管理员的提示。

`POST /api/attendance/corrections` 补记漏签提供 `memberId/businessDate/campusId/timeMode: duty_start/reason/requestId`，不提交日期时间、记录或场次 ID。服务端按所选日期、校区查找或准备场次，采用本人该校区当天最早班次的开始时间，无排班采用默认 19:00。记账时间来源以 `checkin_source.timeBasis: duty_start` 和审计记录保存，不冒充精确到场时间；操作时间独立保存。班次时间纳入并发快照，解析后发生变更则拒绝。旧客户端提供 `occurredAt` 的格式继续校验后兼容。

已有记录使用 `recordId/eventId/memberId/revision/occurredAt/reason/requestId` 修正，界面只允许选择当天的时分，日期取原记录所属日期；服务端也明确拒绝值班跨日修正。实际时间修正后清除默认记账标记，保留首次签到来源、版本与审计。准备场次不产生签到。时间必须在该场次窗口内且不晚于现在，目标有效性、授权、暂停服务与事实版本在提交事务内检查，历史操作不改变实时在岗。

`GET /api/me/volunteer-summary` 只从当前会话获取成员，返回本月、累计时长及 `settings/asOf` 核算依据。与管理月报共用 `calculateVolunteerReport`，包括按周起始日归属月份和负责人每周计入的原有规则。本人范围先在取数时过滤，校区权限再在聚合前应用；默认计入不生成签到。
