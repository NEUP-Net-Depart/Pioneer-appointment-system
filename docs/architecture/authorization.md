# 授权与字段范围

业务基线是 [业务规则](../requirements.md)。维修与业务管理范围由有效账号、真实任职和校区直接决定，不通过维修资格或工作权限包授权。

## 维修与管理

查询及“今日工作”入口使用 repair.summary.read 和现有授权校区范围，系统管理员及其他具备工单查看权限的工作人员均可进入查看；入口可见不授予接收或维修权限。repair.receive 与 onsite.create 要求当前有效办公室任职或硬件部任职；repair.start、repair.transfer、repair.finish.own 要求当前有效硬件部任职，包含硬件部交流任职。兼任按全部有效任职取并集，不以主部门过滤；已结束、未生效或部门停用的任职不提供操作权限，系统管理员身份也不代替业务任职。签到、排班、职级和已有工单数不阻断维修。列表和搜索候选不输出联系方式；单单详情读取必要联系方式并审计访问对象、人员、时间。

部长和副部长管理负责校区内全部部门的资料、排班和考勤；站长、副站长、主席、副主席管理全部校区。成员资料以成员所属校区作对象范围。真实任职有效期采用左闭右开区间，过期和未生效任职不提供当前管理权限。任职、授权校区和启用状态变化使已有账号授权版本失效。

`staff_access_campuses` 汇总明确校区授权及当前站长/主席任职产生的全部校区访问范围。服务读取与数据库工单写入守卫使用同一范围。部门不再限制业务管理。具有当前维修权限的原主修可更正本人结束工单的结果和说明；上述管理人员可以在范围内代改。

预约容量、放号时间、公告、暂停维修日期和维修地点统一使用 `booking.manage`，按当前有效主任职自动判断：副部长和部长仅管理所属校区，副站长、站长、副主席、主席及超级管理员可管理两校区；实际范围与账号当前授权校区取交集。普通部员及仅有 `settings.manage` 的账号不因此取得预约配置权限。入口与校区选项使用同一服务端权限结果，读取和保存仍独立校验目标校区。

## 系统边界

账号、角色模板、系统配置及全局审计由独立系统权限管理，业务负责人不会因任职自动取得这些权限。本人授权和受保护系统账号不可由普通资料管理修改。设置跨校区管理职位需要覆盖全部校区的管理权限。

保留的系统角色授权仍采用 permissionCode、scope、conditions、validity；保存和使用均校验配置与对象范围。业务固有权限不再接受角色模板配置。角色绑定只包含明确的系统授权，不再生成组织任职对应的工作权限包。

0047 完整归档并删除 technician、exchange、office、repair_lead、office_lead 工作权限包及绑定，并删除 effective_member_roles 推导视图。真实任职、人员、签到、历史身份快照和全部原审计保留。历史 0042 的一次性准备脚本仅用于满足不可改写迁移的前置条件，随后统一执行 0047；应用没有旧资格回退路径。

## 考勤与报表

签到资格直接使用真实硬件、办公、交流及负责人身份，现场签到码、业务日期与签到窗口沿用现有规则；普通维修权限不会自动生成考勤。负责人可在对应管理范围出示签到码及补记，补记分别保存到岗事实时间和实际操作时间。

周报原有全部签到、首次签到、负责人周计一次选项及月报原有小时换算参数均保留，仅改为直接读取任职身份。默认计数不生成签到事实，维修数量及持续时间不参与时长核算。未引入月度封顶、跨月结转或学期清零。

## 数据边界

普通部员仅取得当前工单事实及处理所需的历史维修结果，不取得维修与交接操作日志、原始登记备注、签名或协议证据。后端从详情和工作台列表中移除这些字段；当前有效负责人及系统管理员可以在授权校区内查看管理记录，沿用既有任职和管理范围判断，不新增可配置业务权限。

列表、详情、搜索、导出和附件均检查当前对象与校区；界面按钮不能替代服务端检查。学生接口采用显式字段投影，当前、历史及关联工单都不返回内部维修说明和操作历史。联系方式修改前后值加密保存，访问日志不复制明文联系方式。

工单写入使用 revision、授权版本和事务内审计；人员、排班与考勤保留各自的并发版本及操作记录。历史查询使用当前操作者管理范围，历史日期不能恢复已经失效的授权。
