# 到场接待、排队与维修分派

## 业务规则

- 办公接待人员或获授权且在所属校区签到的负责人扫描客户维修码，核验设备并拍摄正反面照片，完成接待后发号入队。工作人员到岗签到码仅用于考勤。
- 各校区每日独立发放稳定号码，离队、取消或删除工单不复用号码。实时排位按到场顺序计算，同一时间以号码区分；号码与排位分别展示。
- 接待手动选择符合资格的空闲维修／交流人员，候选显示身份及当天接单、完成数量。无空闲人员时继续排队；越序分派须填写原因，并在提交事务内检查队首。
- 已分派工单仍计入排队中，立即占用接手人的一单名额。当面核对并确认后才开始维修，其他人员不能抢接；待接手工单不阻塞其他队列工单的正常分派。
- 接手人可更正核验信息、替换照片；保留照片必须属于本工单且经过接待核验。退回须填写原因，保留原号码和到场顺序；获授权的负责人也可填写原因撤回分派。
- 普通维修／交流人员可直接核验接单，但已有队列时只能接未分派的队首。所有入口均校验资格、校区、签到、在岗、工作窗口及一人一单限制。
- 排队、待接手工单不自动过期，跨日保留。改约关闭旧现场流程，保留原单号和查询凭证，重新到场须重新接待。普通改约遵循开放日期、时段、容量、暂停和重复预约限制。
- 校区暂停维修时禁止新增接待、分派和开修；已有工单仍可退回、撤回、取消或改到开放日期。当前无开放时段时保留队列。
- 客户凭私密查询凭证退出排队，接待或负责人也可填写原因标记离队。离队保留预约及原有效期，释放接手人；再次到场须重新核验拍照、取得新号码并排至队尾。退出排队与取消预约分别确认。
- 叫号后暂时找不到客户时保留原位置；接待或负责人可填写原因越序分派，维修人员自行接单不能越序。

## 页面与交接

接待和负责人协调共用“现场工作台”（`desk`），旧 `operations` 场景归一到此入口；能力按当前校区授权显示。顶部“未到场 n/m、排队中、维修中、空闲中”同时作为筛选，重复点击取消选中。m 为今日非取消的实际工单数（含现场登记），n 为其中尚未接待、未离队的已预约工单数；跨日排队和维修继续显示，空闲人数仅统计可接单成员。

工单进度显示“已到场、待分派、待接手、维修中、已完成”。接待和接手页在核验前展示返修轮次、本次原因与上轮处理结果；摘要、核验表单和确认勾选统一使用当前核验信息，原始填写内容收在“原始登记与协议”。更改设备型号、厂商、核验选项或照片后须重新确认。

正反面照片直接展示缩略图，支持放大、替换和加载失败重试。关闭放大图后焦点回到原按钮，Esc 仅关闭当前弹层。手机端主操作固定在弹窗底部，内容独立滚动；状态使用简短小字，不增加指导性说明。

用户从原单链接进入时，优先看到当前返修的状态、排期、地点、单号和维修码；存在未完成返修的维修链列入“当前预约”，上轮资料与结果默认折叠。页面可见时每 30 秒刷新排位，隐藏时暂停；刷新保留维修码、展开状态、退出确认和键盘焦点。办公人员安排返修后显示含新单号、校区、日期和时段的回执，工单入口遵循当天资料权限。

现场登记可展示客户私人查询二维码，与客户维修码、工作人员到岗码区分。查询凭证复用加密登记回执，仅向有资料权限的登记人提供；凭证轮换后不恢复旧凭证，没有回执的历史登记不生成新凭证。

## 状态、权限与事务

预约主状态保持 `booked / in_progress / completed / cancelled / expired`；`repair_receptions` 保存现场阶段 `queued / assigned / started / closed`。仅当预约为 `booked` 且现场阶段为 `queued / assigned` 时替换展示状态，改约关闭现场流程后显示“已预约”。

`repair.receive` 负责接待，`repair.dispatch` 负责分派、撤回、改约和取消；普通维修人员仅可退回本人的待接手工单。所有命令独立校验权限，入口合并不扩大授权。历史资料按预约日期及完整对象范围授权，跨日队列仅保留现场摘要和当前处理能力；姓名搜索、计数与详情遵循相同范围。操作使工单超出详情权限时，命令及重试回执仅返回结果，页面返回工作台。

数据库按稳定 `memberId` 限制一人一单，阻止抢接、暂停日分派及带单离岗。工单版本、签到版本、授权版本、工作窗口、设备核验、发号、审计和回执在同一事务内校验或写入；失败整体回滚且不消耗号码。网络响应丢失时以原请求编号和版本重试一次，再查询实际工单；权限或业务冲突不自动重试。

工作量按当天接单／转派与完成审计统计，兼容 `repairs.started`、`repairs.claimed`，并按工单去重；缺少审计的历史记录由开始／完成事实补足。客户响应不返回工作人员账号或内部成员编号。

## 返修与接口

返修单保留 `onsite / repair_followup`，允许改到已满但仍开放的时段；普通改约仅列有容量的有效半小时时段。两者均保存目标日期地点快照，并在提交时校验停修、排期及容量约束。

原工单私人链接可查询后续返修的排号和排位，维修码沿同一后续关系解析。查询时同步处理整条维修链中未到场或已离队工单的到期状态。退出返修队列时事务重新核验凭证和父子关系；凭证轮换使旧链接失效，旧离队回执不影响再次入队。

| 接口                                                                 | 用途                                                                                               |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `POST /api/appointments/:id/reception`                               | `receive / assign / return / withdraw / leave / reschedule / cancel`，携带 `revision`、`requestId` |
| `POST /api/appointments/:id/queue-exit`                              | 客户凭 `X-Appointment-Token` 退出，携带 `revision`、`requestId`                                    |
| `POST /api/appointments/:id/repair-followups/:followupId/queue-exit` | 原单凭证退出关联的后续返修队列                                                                     |
| `GET /api/field/appointments/:id/dispatch-candidates`                | 当前可接单人员                                                                                     |
| `GET /api/appointments/:id/reception-options`                        | 可改约日期和时段                                                                                   |

现场首页、列表、详情、预约记录、编号搜索与用户查询复用现场阶段投影。

## 迁移与验证

dev 和 Staff Staging 两条迁移链均追加 `0039_reception_dispatch.sql`、`0040_reception_queue.sql`，不修改旧迁移。0039 按既有接待／转派授权复制权限，保留范围与有效期；0040 按原到场顺序补号，独立保存每日计数器。无接待记录的旧工单继续走原核验接单流程。

- `tests/reception-dispatch.test.mjs`：真实 API 流程、权限范围、照片归属、竞争与回滚、跨日、改约、暂停、凭证轮换及返修关系。
- `tests/reception-queue-upgrade.test.mjs`：历史接待升级、每日计数器及迁移约束。
- `npm run test:field`：接待、分派、退回、接手、完成及返修交互；包含 `reception-ui.spec.mjs` 的照片预览、型号更正、维修码保持及移动端操作。
- `npm run test:layout`：Chromium、Firefox、WebKit 布局与滚动条回归，覆盖 320 / 390 / 768 / 1440px。
- `npm run db:verify`：两条迁移链的新建、重复执行和外键校验。

`npm run preview:field` 创建隔离的本地 D1/R2，终端输出预览地址和管理员凭证文件位置；不修改远程资源。
