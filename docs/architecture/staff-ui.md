# 后台操作层级

本次调整依据现有业务规则、角色权限、接口和页面操作梳理；项目没有操作频率埋点，因此以下频率是按业务发生周期判断，并非使用量统计。

## 业务路径与常用操作

| 场景 | 业务路径 | 高频入口 | 后续管理 |
| --- | --- | --- | --- |
| 接待 | 查单或扫码 → 核验拍照 → 排队 → 分派 | 扫描客户维修码、现场登记、现场队列 | 转派、纠错、返修 |
| 维修 | 到岗签到 → 接手 → 记录维修 → 完成 | 当前维修、队首工单、设备查询 | 保修查询、历史工单 |
| 排班 | 发布收集 → 填报 → 结束收集 → 排班调整 → 检查发布 | 当前周任务、当前阶段主操作 | 需求、任务设置、导入 |
| 考勤 | 到岗事实 → 请假审核／历史修正 → 核算导出 | 请假审批、考勤核查、报表 | 核算规则 |
| 人员 | 建档／导入 → 任职和参与身份 → 激活 → 账号使用 | 查找成员、新增人员、批量导入、激活审核 | 部门、角色权限、资料补全 |
| 预约运营 | 名额与地点 → 开放日期 → 放号与公告 | 预约查询、当日及待处理筛选 | 预约配置 |

## 导航层级

- 现场工作：岗位工作台、预约记录、统计分析。
- 排班考勤：维修排班、办公排班、请假审批、考勤核查、报表导出。
- 人员权限：人员管理、角色与权限。
- 业务设置：预约配置。
- 我的：个人中心、班次与排班、本人签到记录、账号安全。

一级导航回答“处理哪类工作”，页内导航回答“处理哪个对象或阶段”，列表筛选回答“找哪一批记录”，记录上的按钮回答“对谁操作”。桌面提供功能搜索，搜索词覆盖扫码、换班、激活、名额等实际操作名称；手机保留有权限的岗位入口、个人班次和个人中心，其余放入同一分组的功能面板。

入口仍由已有权限检查生成，展示层只负责排序、分组、图标和搜索。所有跨页操作仍经过未保存修改保护；已加载的筛选、数据和草稿继续保留。

## 视觉与交互

沿用现有灰白背景、深灰主按钮和业务状态色。用位置、留白、线框图标、选中边线和明确动词区分层级，不引入说明性小字。主要动作始终直接可见，低频维护放入已有的“更多操作”组件；必要的错误、危险操作确认与业务事实保留。

页面头部承担标题和页面操作；页内标签用下划线呈现当前对象；筛选使用独立控件，避免与页面导航混淆。已有流程中的约束、权限与数据写入行为保持由原业务代码控制。

## 已落地的操作调整

| 页面 | 调整 | 操作收益 |
| --- | --- | --- |
| 工作导航 | 五组业务入口、线框图标、桌面功能搜索、手机岗位入口；分组内顺序固定 | 按工作找入口；可用“密码”“换班”“激活”等操作词查找 |
| 现场工作台 | 扫码为主操作，登记和签到码并列；列表展示核验、分派或查看动作 | 不打开详情也能知道工单的下一步 |
| 现场概览 | 数字卡片直接筛选；切换人员与队列时选中状态同步 | 从空闲人员返回排队工单时，不会误清除队列筛选 |
| 到岗核查 | 待签到人数配“查看到岗”；空闲人员配“显示全部人员” | 从待办直接进入可处理的列表 |
| 预约记录 | 直接展示常用状态、今日／本周／不限日期；保留精确日期、时段、校区及历史状态 | 高频筛选一次点击；组合条件与跨页返回保持 |
| 预约记录 | 空返修队列收起，存在待处理申请、错误或处理结果时展示；导出放入更多操作 | 将列表空间留给当前任务，处理结果仍可见 |
| 人员管理 | 新增、批量导入直接可见，批量补学院放入更多操作；账号子级用独立分段样式 | 建档与日常查找优先，父子导航易区分 |
| 排班管理 | 新建任务强调为主操作；沿用步骤条和当前阶段主按钮；长说明替换为草稿／生效等状态 | 当前阶段和下一步更直接 |
| 个人中心 | 今日安排与“我的工作”并列，集中班次申请、签到记录、账号安全 | 避免在个人中心重复管理菜单 |
| 全局布局 | 修复长页面的侧栏固定、手机工单动作被旧样式隐藏的问题 | 小高度桌面和窄屏仍可操作 |

复用项目现有 Modal、WorkspaceSections、WorkspaceMoreActions、权限检查和草稿保护，不增加依赖。

## 验证范围

- `npm run verify:checks`：格式、lint、类型、架构、构建、自动测试、数据库迁移验证。
- 工作区启动、按需加载、数据连续性、人员编辑、预约查询与排序、扫描器生命周期回归。
- 新增操作回归：组合日期筛选保留查询与校区、功能关键词搜索遵守权限、现场工单下一步在窄屏可见、人员与队列切换保持正确筛选。
- 隔离 D1／R2 夹具验证真实接待、接手、完成、转派、排班、考勤及返修链路。
- Chromium、Firefox、WebKit 的手机／桌面首次布局，以及 320、390、768、1440 像素下的后台页面和弹窗。

自动化可验证功能、权限和布局约束；首次使用的理解程度仍需由实际使用者试用确认。预览使用本地隔离数据。

## 电脑端专项调整

- 左栏默认只展开当前业务组，切换组时收起前一组。1366 × 768 的管理员工作台可同时看到五个业务分类；低高度窗口保留侧栏独立滚动、账号固定和键盘焦点自动滚入视野。查找功能支持 Ctrl/⌘ K，输入操作词后按 Enter 打开首项，仍经过原有草稿保护；弹窗打开时不抢占快捷键。
- 现场工作台缩减概览卡片和到岗提示的垂直留白，桌面将队列标题、数量和搜索放在同一行。1366 × 768 的夹具中，三条预约及其核验动作均完整出现在首屏。订单与人员在宽屏并列，人员区在长队列滚动时停留，长人员名单独立滚动；小高度窗口恢复普通文档流。
- 预约记录将快捷日期与结果数量合为一行，搜索框利用剩余宽度，折叠的概览缩为普通工具条高度。状态、日期、校区和排序的组合逻辑保持原样。
- 人员列表把查找、校区、状态与新增／导入放入同一工具栏；姓名与学号并排，身份置于第二行，学院归入部门列。桌面可横向扫读更多成员；窄屏仍使用现有卡片布局。
- 超宽屏限制内容区最大宽度，人员侧栏保持稳定宽度；排班空状态的起步动作与状态分开排列。未新增配色、依赖或说明性小字。

桌面回归包含首屏可操作记录、全部业务分类可见、人员工具栏对齐、500px 高度导航可达、键盘查找与未保存修改保护，并继续验证 320／768px 的原有操作。

本轮验证结果：70 项界面回归已通过（包含失败修复后的复验）；53 项业务场景中，51 项在 Chromium 通过，人员管理刷新与容量编辑两项在 Chromium 自动截图阶段发生原生进程崩溃，已在 WebKit 中完整复验通过。Chromium、Firefox、WebKit 的 48 项首次布局检查，以及格式、类型和 lint 检查全部通过。预览截图另外核对了 1366 × 768 的实际首屏，第三条预约底部位于 736px，导航无需滚动。
