# Issue #20：双设备预约评审与验收

## 范围

- 一台设备仍对应一张工单；普通单台请求格式不变。
- 一次提交最多两台，共用客户资料、签名及到场范围，各占一个名额。两台原子提交，任一失败整批回滚。
- 每学号每天跨校区最多两台普通线上预约；`booked`、`in_progress`、`completed` 计入，`cancelled`、`expired` 不计入。现场登记和返修沿用既有独立规则。
- 在原预约详情中补约一台需原单私人凭证；原单必须仍为已预约，补约锁定学号、校区、日期、时段，其他预约限制正常生效。

## 关键实现与评审顺序

1. `shared/booking-devices.js` 与 `src/lib/validation.js`：设备字段白名单、两台上限；嵌套设备不能覆盖客户身份或到场范围。
2. `migrations/0041_multi_device_booking.sql` 及同名 Staff Staging 迁移：数据库每日限额、批次回执、原单关联。只追加迁移；历史记录不改写。新增迁移指纹追加至既有基线清单，未变更历史指纹。
3. `src/db/appointments.js`：一次 D1 batch 提交两单及所有回执／关联。补约在同一事务内复核原单版本、凭证和状态；并发取消、修改或补发凭证使整批回滚。
4. `src/services/appointments.js`：复用原单台预约验证、加密和公告规则；原单台摘要及返回格式保留。批次回执恢复逐张验证凭证，任何一张被移除／补发均不回传旧凭证。
5. `frontend/user/booking.js`、`second-device.js`、`slot-picker.js`：复用设备字段结构，客户信息只填写一次；每台照片各自压缩上传。两台时禁选只余一位的时段。成功后按设备切换二维码、私人链接和照片状态，分别保存凭证。
6. `frontend/user/lookup.js`：原单补约入口及关联设备摘要。补约前若存在其他草稿，先在页面内确认放弃；已有未确认提交须先核实。恢复旧提交结果时不把新选择的照片自动附到旧工单。

## API 示例

`POST /api/appointments` 保留 `Idempotency-Key`。普通单台沿用原平铺字段；两台在共同字段外附带：

```json
{
  "devices": [
    {"deviceType":"笔记本","brand":"联想","deviceModel":"T14","warranty":"否","liquidMetal":"不清楚","faultType":"蓝屏","issue":""},
    {"deviceType":"台式机","brand":"Apple","deviceModel":"Mac mini","warranty":"否","faultType":"黑屏","issue":""}
  ]
}
```

以上片段不含原接口已有的必填客户资料、日期、签名与协议确认，不能独立发送。成功返回保留第一张预约的字段，并附加 `appointments` 数组；每项均有各自的 `id` 和 `accessToken`。结果恢复接口返回同一结构。

补约使用单台请求，增加 `additionalFor: 原预约编号`，并在 `X-Appointment-Token` 中携带原单凭证。不能凭学号或公开二维码补约。

## 人工验收路径

1. 选择两台设备及一个至少剩余两位的时段；分别填写不同品牌、故障与照片，核对页应呈现两台、一次机主资料；签名提交。
2. 在成功页切换两台设备，检查工单号、维修码、私人链接和照片各自正确；“我的预约”出现两单。
3. 取消第一单，第二单应保持有效；返回第二单详情补约，学号与到场范围不可修改，新设备信息需重新填写及签名。
4. 用同学号在另一校区尝试第三台，应拒绝；已完成的同日工单仍计入两台限额。取消／过期后允许在其他约束满足时重新预约。
5. 将所选时段调整为只剩一个名额，提交两台应全部失败，无单号／回执残留。并发提交不同请求不得超过每日限额及实际容量。
6. 两台分别接待、发号、接单、完成、申报返修，互不改变另一张工单；每位维修人员仍只能有一张维修中工单。
7. 模拟提交响应丢失，用原请求键重试应恢复原两单，无重复预约。恢复后需按设备详情补传照片。
8. 在 320、390、768、1440px 查看数量选择、长字段、第二台设备、核对、成功切换和补约确认。

- `tests/multi-device-upgrade.test.mjs`：两条旧库迁移链逐字段保留预约和原请求回执，验证升级后两台限制及恢复取消的约束。
- `tests/cutover-release.test.mjs`：既有部署快照升级、就绪检查、部署资源冒烟。
- `tests/e2e/multi-device-booking.spec.mjs`：Chromium 与 WebKit，独立照片、凭证切换、草稿恢复、补约和四种宽度；浏览器 API mock 配合上述真实后端测试。
- 既有学生预约浏览器回归、全后端测试、lint、类型检查、架构检查与 D1 迁移重放。
