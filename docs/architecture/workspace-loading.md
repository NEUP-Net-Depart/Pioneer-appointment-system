# 工作台查询缓存与后台更新

人员、预约记录、账号列表和个人值班通过 `useWorkspaceQuery` 读取数据。首次没有缓存时显示既有页面结构；有缓存时直接展示，读取新数据不应禁用已有行、筛选或编辑入口。

## 缓存范围

- 缓存只在当前会话的内存中保存，不写入浏览器持久存储。
- 账号、授权版本或权限范围改变，以及退出登录，都会清空工作台缓存，并通知查询组件停止使用旧会话结果。
- 按接口路径分组，完整查询参数区分结果；每组以八组结果为淘汰上限，正在使用的结果受保护，不为腾出缓存而清空当前区域。未被当前组件持续持有的缓存保留五分钟。组件中已经显示的结果在网络故障时继续保留，重新校验不先清空它。
- 完整的人员集合可以派生校区、状态筛选；未加载完整的集合不用于断言筛选结果为空。关键词搜索仍由服务端执行，避免遗漏非主部门等匹配。

## 更新与分页

- 每三十秒检查一次是否需要校验；普通结果的新鲜期为三十秒，已展开多页的结果为两分钟。新鲜缓存不重复请求，页面或浏览器标签隐藏时暂停查询。
- `loading` 仅表示没有可用数据的首次加载，`refreshing` 表示保留数据的后台校验，`loadingMore` 表示追加下一页。不能用 `refreshing` 禁用整个页面。
- 列表首次只取一页，滚动接近尾部时追加。后台刷新最多重取已经展开的页数，不抓取尚未浏览的完整集合。
- 多页刷新使用新的游标链，在全部成功后一次发布。中途失败保留完整旧快照，避免新首页与旧尾页混用；用户主动追加下一页会取消正在进行的后台刷新，优先完成追加。
- 所有请求都受路径、会话和取消信号约束。失去授权会清空对应查询组，而普通网络错误保留现有数据并呈现可重试错误。

## 保存与草稿

- 经工作台 `request` 完成的写操作会将查询缓存标记为待校验；调用方递增 `revision` 可立即刷新当前区域。未经过该入口的写操作需要主动调用 `invalidateWorkspaceQueries` 或其专用刷新机制。
- 写入前启动、写入后才返回的查询不能发布旧结果，会重新读取。标记过期不会先删除已有显示内容。
- 编辑表单保留自己的草稿和打开时的业务版本号；不能把后台更新得到的新版本号与旧草稿组合提交。个人值班的空闲编辑已按此处理。
- 今日工作沿用 `useField` 的校区、业务日期和权限降级规则，同样区分首次加载与后台刷新；不要绕过其授权处理来复用普通查询。
