# 身份与组织映射

`members.id` 是稳定的人员标识，排班、签到、维修和审计继续使用该标识。`staff_accounts.member_id` 关联唯一登录账号，停用账号不会删除人员或历史。账号类型不代表组织职位，也不自动生成维修身份。

| 实体 | 职责 |
| --- | --- |
| `members` | 姓名、学号、所属校区、学院专业和状态 |
| `departments` | 固定部门及轻量站点、中心单位；权限按稳定代码判断 |
| `member_department_memberships` | 正式部门与职位，或指向硬件部的交流关系；左闭右开有效期 |
| `effective_member_roles` | 只读视图：组织推导身份与特殊显式授权的并集 |
| `member_roles` | 有校区、有效期和原因的明确特殊授权，含受保护系统身份 |
| `staff_campus_grants` | 账号业务校区的唯一权威来源，与所属校区独立 |
| `attendance_records` | 发生时的姓名、部门和身份快照，调岗不改写历史 |

同一时刻只有一个正式主部门。晋升或调岗在同一事务中结束原任职并创建新任职，保留历史。任职表只保存真实正式任职与交流；站级和中心级职位在相应组织单位表达。结束正式任职即撤销对应自动角色，离任留任必须另有明确特殊授权。

硬件部正式部员自动使用 technician 模板，副部长、部长另有 repair_lead。设备服务站副站长、站长与中心主席、副主席只有管理能力；其他同级职位没有默认维修管理权限。非硬件部交流关系自动使用 exchange 模板，不参加正式维修排班和换班。留任通过特殊授权表达。自动身份不写入 member_roles。

0042 一次性将旧任职、角色绑定、工作资格完整归档到 audit_events。每位旧成员必须在仓库外的私有文件中明确确认真实任职、交流、带范围和原因的特殊授权，或撤销旧身份；缺少决定、身份不匹配或源数据变动均中止。旧 admin、technician 和系统推测的部门不是职位或特殊留任依据。工作授权只按核实的原范围及有效期填写，不重开结束授权，不扩大账号校区。转换后删除旧工作资格表及全部迁移用表，无运行时核对状态或资格兼容字段。

0042 发布前核查生产及 Preview 的 d1_migrations；已执行的迁移不得覆盖。2026-11-01 的只读检查确认两边均未执行 0042，可直接修正该文件。生产的完整历史迁移链及 Preview 的 0041 升级路径均以只读快照在本地演练；成员 ID、账号密码、账号校区和业务历史必须保持，失效旧会话不改变密码。

私有名单按学号或成员 ID 匹配并校验姓名，不按同名自动关联，也不为未建档人员创建账号。有效期结束日使用不含当天的数据库边界。已确认人员不保留旧默认绑定；0033 仅凭 admin 生成的工作资格也不作为留任证据。名单、快照和生成的 SQL 均不得入 Git，操作见部署与运维。

人员新增和 CSV 导入共用一个服务。CSV 字段为 studentId、name、homeCampusId、college、major、departmentId、positionCode、exchangeParticipation、authorizedCampuses、configureActivation、effectiveFrom。完全重复关系跳过，真正重叠列为冲突。已有账号校区默认保留，只有显式 replace、相应校区权限和匹配预览才能替换；空字段不会清空授权。

激活前校区保存在 whitelist_campus_grants，批准时原子复制到 staff_campus_grants，并关联原成员。配置和批准均校验当前完整授权，提交时再次检查人员快照、模板版本及审批人会话。普通非维修成员可只建档。受保护账号不能通过普通成员、导入或角色绑定接口修改。
