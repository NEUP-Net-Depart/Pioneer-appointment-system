# 身份与组织映射

`members.id` 是稳定人员标识。账号唯一关联成员，停用不删除任职、维修、签到或审计历史。历史普通账号类型 `technician`、`admin` 均显示为“工作人员”，不据此标注维修或管理身份；系统账号显示为“系统管理员”。接待能力取当前有效维修事务或硬件部任职，维修能力取硬件部任职（含交流维修），并检查授权校区。

| 数据 | 当前用途 |
| --- | --- |
| members | 姓名、学号、所属校区、学院专业、状态 |
| member_department_memberships | 正式部门任职、交流维修、维修事务，左闭右开有效期 |
| staff_campus_grants | 配置的账号校区范围 |
| staff_access_campuses | 配置范围加有效站长、主席等全校管理任职的双校区范围 |
| roles / member_roles / role_grants | 系统设置、账号、权限等剩余可配置能力；不能制造维修资格或业务管理身份 |
| attendance_records | 实际发生时间、录入时间、当时姓名/部门/身份快照 |

同一时刻一个正式主部门。调岗或晋升结束旧任职并创建新任职，保留历史。部长、副部长管理当前授权校区各部门；所有站点的站长、副站长及中心主席、副主席管理全部校区。固定业务权限不在角色编辑器中配置。受保护系统账号与自提权限制继续独立执行。

结束任职允许选择生效当天，默认选择今天（尚未生效的任职默认选择生效当天）。结束日期当天起不再有效；同日生效、结束的记录作为无有效日期的历史保留，不提供权限，也不占用其他任职的有效期。保存结束操作时同步更新授权与会话版本，使后续请求不再沿用该任职权限。新增任职的预设结束日期仍须晚于生效日期。

人员列表、详情和账号列表共用任职身份名称。“工作人员”是平台人员的统称；正式部门与职位展示为“硬件部部员”等具体任职；“交流维修”“维修事务”是可并存的独立身份，不展示为某部门的另一份正式任职。创建、导入、任职编辑采用相同名称，新增独立身份不要求用户选择部门。同类独立身份不允许有效期重叠，历史保存的不同部门关联也不能被当作新增身份绕过重复校验。额外系统授权单独展示，不以“尚未授权”误指该人员没有业务身份或权限。

身份用于展示、责任和原有考勤核算。硬件部、交流维修、维修事务与有效管理任职参与既有出勤资格判断，办公室部门本身不提供额外资格，不自动生成出勤或时长。周/月报在原计算代码中直接读取这些任职与新班次事实。

0042 是不可修改的历史人员确认迁移；未执行该迁移的旧库仍须满足其一次性输入约束。0047 追加归档并移除维修/办公/交流/业务负责人工作权限包、独立资格和 effective_member_roles 视图，保留原任职、人员及审计。运行时不再读取旧资格、推导角色包或回退旧模型。

激活管理和审核权限由当前有效管理任职提供，不需要额外分配。单人创建和 CSV 导入默认建立新成员的待激活资格，未指定授权校区时采用所属校区，不再提供“配置账号激活资格”开关。旧的未配置记录在有权限的负责人打开账号信息时通过带版本校验的写入补齐默认资格；页面只展示状态，无独立配置按钮。已有明确撤销的资格不被默认逻辑重新开启。成员仍须自行提交申请并经核验批准，随后原子创建账号并复制校区授权，不做维修资格审批。CSV 导入与单人创建共用规则，冲突或预览后的数据变化整批拒绝。系统账号和授权修改另行校验，普通资料管理不能绕过受保护账号限制。详细授权见 [authorization.md](authorization.md)。
