# 业务规则与权限

字段及长度限制以 [输入校验](../src/lib/validation.js) 为准，部署命令见 [部署运维](operations.md)。

## 预约

| 项目 | 规则 |
|---|---|
| 访问 | 学生免注册；查询、取消及附件须使用私人凭证；学生端没有排队排名／人数看板 |
| 时间 | `Asia/Shanghai`，今天至第 3 天，仅周一至周四；19:00–21:00 分为四个半小时段（19:00–19:30、19:30–20:00、20:00–20:30、20:30–21:00） |
| 容量 | 按校区、工作日和半小时时段配置，默认每段 5 人；日期首次预约后冻结，修改仅影响尚未预约的日期 |
| 名额 | 仅取消释放容量；同学号同服务日最多一条有效线上预约，跨校区和时段同样受限；已完成计入，取消／逾期不计，现场登记不计 |
| 取消 | 学生只能取消自己的 `booked` 预约 |
| 编号 | `reserve{校区代码}{YYYYMMDD}-{序号}`；南湖 0、浑南 1，所有时段共用序号、不回收 |
| 协议 | 提交前同意协议并手写签名；免费维修，配件自备，普通硅脂由中心提供 |
| 学生故障照片 | 选填，最多 4 张，JPG／PNG／WebP，单张最多 2 MiB；先在本机压缩，创建成功后逐张上传，保留 180 天 |
| 工作人员／历史附件 | 授权工作人员保留 JPG、PNG、WebP、PDF、UTF-8 TXT 上传能力，通用文件最多 5 MiB；旧附件继续凭证受控读取 |
| 地点 | 按校区＋具体日期配置，未配置不可约；工单保存快照，详情展示该服务日最新地点和变更提示；变更审计并由管理员人工通知 |
| 创建 | 随机 Idempotency-Key、输入摘要和 D1 事务收据保证同次重试不重复创建；同键不同输入拒绝 |
| 签到照片 | 选择照片后自动压缩并上传，确认签到后才进入维修中；须由本次签到人上传正、反两面照片，每张最多 2 MB，保留 180 天 |

签到照片自动校正方向，最长边 2560 px，JPEG 初始质量 0.85，期望大小 1–1.5 MB，硬上限 2 MB。压缩失败须提示原因；支持 JPG、PNG、WebP 且不超过 2 MB 的原图可回退上传。无法转换的 HEIC/HEIF 须转为 JPG 或重新拍摄。

名额、预约状态／结果／地点约每 30 秒刷新，隐藏暂停、切回立即更新；网络失败保留已确认信息。新预约在到场时段结束后不可创建，已有预约仍有效至当日 21:30。旧小时段只保留历史读取。完整协议见 [用户页面](../frontend/user/index.html)。

## 学生三步界面

校区与到场时间 → 设备、故障、机主与联系方式 → 核对、协议与独立手写签名。校区、时段无预选；选校区后展开最近可约日期。时间或地点失效返回第一步，保留其他输入和有效签名。

| 表单分组 | 规则 |
|---|---|
| 设备 | 笔记本／台式机／其他；品牌必填、支持手填，型号选填。笔记本／台式机必答液金散热，笔记本＋Dell 显示选填 G15 问题。液金、G15、在保均区分是／否／不清楚；在保必答，只提示官方售后。学生不再填写序列号、进液／跌落 |
| 故障 | 清灰换硅脂、换硬盘、换内存、系统问题、蓝屏、黑屏、网络问题、其他，必填单选；统一说明最多 1000 Unicode 码点，其他故障必填，其余选填 |
| 机主与联系 | 姓名、学号、学院及 QQ／微信二选一账号必填；邮箱选填。学院、品牌配置见 [student-booking.js](../shared/student-booking.js)，学院不按校区过滤；隐藏字段和未选中的联系方式不提交 |
| 照片 | 最长边 2560px，JPEG 质量从 0.85 至最低 0.7，目标 1–1.5 MiB、硬上限 2 MiB。准备失败须替换或移除；不强制相机，不支持视频；浏览器无法解码的 HEIC/HEIF 提示改用 JPG 或重拍 |
| 协议与签名 | v1.1，一个同意复选框和独立全屏签名；阅读不自动同意，取消重签保留原笔迹，不比较姓名；前后台拒绝空签名和单次点击 |

成功页展示服务端确认的时间、地点和默认展开的维修二维码，不自动跳转。照片逐张上传，已成功的不重复上传，失败可重试或在详情补传，不撤销预约。

我的预约分当前与历史两组，历史默认可见；维修中优先、已预约按到场时间升序、历史按日期降序。卡片进入独立详情，展示地点变更、维修结果、附件及补传入口；仅 booked 可原位确认取消，响应不明先查询真实状态。重新预约为空白表单，有草稿时确认舍弃。

草稿保存在 sessionStorage，约两小时，仅保存文本和选择；主动确认恢复并重新校验时间、地点、容量，不恢复照片、协议或笔迹。创建结果不明保留原幂等键；成功后清理草稿。浏览器无法保存私人凭证时保留会话访问并提供完整私链复制。

## 学生接口

预约详情、取消、二维码及附件均使用 `X-Appointment-Token`；管理员接口使用现有 JWT 与校区授权。错误返回 `{error, code?, fields?}`，字段错误关联到控件；满额、暂停、时段结束、日期或地点失效返回第一步，同日学号冲突不透露已有预约信息。

| 接口 | 契约 |
|---|---|
| `GET /api/booking-availability?campus=...` | 返回 serverNow 及窗口内各日地点、容量、占用；可带 date 查单日 |
| `POST /api/appointments` | `Idempotency-Key` 必须为 32 字节随机值的 43 字符 base64url 编码；提交表单、agreementAccepted、agreementAt、agreementVersion、signature，返回工单及 accessToken。同键重试取回原结果，不同输入返回 IDEMPOTENCY_MISMATCH |
| `POST /api/booking-attempts/resolve` | `{requestKey}` 核实创建结果；found:false 不代表原请求确定失败，继续使用原键；CREDENTIAL_ROTATED 表示已创建且凭证已补发 |
| `GET /api/appointments/:id` | 最新状态、结果、地点、原地点快照与附件；兼容历史维修号别名 |
| `PATCH /api/appointments/:id/status` | 学生仅可提交 `{status:"cancelled", revision}` |
| `GET /api/appointments/:id/scan-code` | 返回 `id.HMAC12`；不含私人 token，工作人员扫码仍需授权 |
| `POST /api/appointments/:id/attachments` | 学生仅上传 JPG／PNG／WebP，≤2 MiB、故障照片总数≤4，用途 student_photo；附件 list/download 同样鉴权 |
| `GET/PATCH /api/service-locations` | 管理员读取日期范围，或提交 `{campus,date,location,revision}`；保存返回变更及需要人工通知的当前预约 |
| `GET /api/service-locations/history?campus=...&date=...` | 授权管理员读取地点审计与受影响预约 |

## 状态与逾期

| 状态 | 数据库值 | 含义 |
|---|---|---|
| 已预约 | `booked` | 等待维修 |
| 维修中 | `in_progress` | 已接单并开始维修 |
| 已完成 | `completed` | 维修结束，有明确结果 |
| 已取消 | `cancelled` | 主动取消 |
| 已逾期 | `expired` | 有效期限结束，未记录维修开始 |

完成维修须填写说明及 `repaired`、`unrepaired` 或 `not_needed`。取消直接提交 `status=cancelled`；取消和逾期的维修结果为空。`pending` 仅为已预约和维修中的组合筛选。

普通预约和临时登记默认在当日 21:30 到期；仅 `booked` 且未记录开始时间的工单自动逾期，维修中工单不自动逾期。不判断学生是否实际到场，也不提供到场确认操作。

> 预约有效期已结束，本次预约未记录维修开始。如实际到过现场，请联系工作人员核实；如仍需维修，可以重新预约。

管理员使用 `action=correct` 纠错。截止后恢复为已预约，须填写 8–300 字 `correctionReason` 并指定未来的 `expiresAt`（含时区）。恢复校验容量，清空原人员、签到照片、维修记录及时间，并要求重新拍照签到；不能直接将未维修的终态工单改为维修中或已完成。

完成、取消、逾期分别统计，逾期率为逾期数 / 总数。历史缺失结果保留 `legacy_unknown`，不计入修复成功率分母，新请求不能填写此标记。

## 扫码维修

- 二维码仅含编号和 12 位 HMAC 校验码；授权工作人员可用扫码、相册或编号定位工单。
- 签到须上传两张不同的电脑正反面照片，记录负责人和开始时间；完成须填写结果和说明。
- 每人同时最多一张进行中工单。刷新或重新登录恢复本人工单，草稿和照片 ID 按账号保存在本机；相同签到、完成请求可安全重试。
- 临时登记仅工作人员可用，不占线上容量或排队；每人最多一条待签到记录，创建者可取消，当天 21:30 起不再新建。

## 角色与激活

| 角色 | 权限 |
|---|---|
| `technician` | 授权校区的待接单设备摘要及本人工单；签到后读取详情、附件，不可转派 |
| `admin` | 授权校区的预约、容量、激活审核、转派、纠错、统计、导出及维修人员账号管理 |
| `superadmin` | 继承管理员权限，可管理低级账号的管理员权限 |

所属校区不自动授予权限。账号管理限于角色低于本人、授权校区均在本人范围内且非保护的账号；停用保留历史。`root001`、`root002` 为受保护的 superadmin，仅本人可验证旧密码后改密。

部员须在白名单内，通过 `/staff/?activate=1` 申请并经管理员核验批准。CSV 必含 `studentId`，可选 `expectedName`、`expectedRole`、`authorizedCampuses`（多校区用 `|`）；单次最多 200 条，格式错误或重复学号整批失败，已有记录跳过。普通管理员仅审核维修人员；待审不可登录，拒绝可重申，撤销资格同时拒绝待审申请。

## 凭证与安全

私人链接用 URL fragment 携带凭证；API 使用 `X-Appointment-Token`，不得放入 query。编号、学号和维修二维码不能替代凭证。凭证遗失须由管理员核验身份后调用 `POST /api/appointments/:id/credential`，提交 `identityVerified=true` 和至少 8 字说明；新凭证仅返回一次，旧凭证立即失效。激活查询使用 `X-Activation-Receipt`。

工作人员 JWT 有效期 8 小时；退出、改密、停用及角色或授权变更撤销会话。附件校验 MIME 和文件签名，加密与持久化约束见 [数据模型](data-model.md)。
