# 业务规则与权限

表单选项与长度限制以 [学生配置](../shared/student-booking.js) 和 [服务端校验](../src/lib/validation.js) 为准，接口以 [路由](../src/routes/) 为准。业务日期使用 `Asia/Shanghai`。

## 学生预约

| 项目 | 规则 |
| --- | --- |
| 访问 | 免注册；私人凭证用于查询、取消和附件访问 |
| 时间 | 各校区每日放号时间由具备配置权限的管理员设置，默认北京时间 10:00；放号前开放当天至后两天，放号后开放当天至后三天，仅限周一至周四。19:00–21:00 分四个半小时时段，各时段结束后不能新约，当日 20:45 统一到期并停止当天新约；签到、排班和统计日期仍按自然日计算 |
| 公告 | 仅在预约首页按校区及北京时间生效范围展示，可选页面或弹窗形式；普通公告无需确认，必读公告须点击阅读按钮后才能进入下一步，未确认时定位聚焦。填写期间公告更新则返回首页重新确认，保留已填信息；确认版本随预约保存。暂停说明与暂停记录共用数据，选中对应日期显示整日暂停提示，恢复或日期结束后停止展示 |
| 名额 | 按校区、周几和时段配置，默认每段 5 人，0 表示该时段不放号；修改立即应用于今天及未来对应日期，过去日期不变。已有预约全部保留，已占用达到或超过新容量时停止新增，低于后恢复。同学号同服务日最多一条有效线上预约；已完成、已过期计入容量，取消及现场登记不计入 |
| 地点 | 南湖默认「大学生活动中心202室」，浑南默认「大学生活动中心308室」；按日期设置的完整地址优先，显式留空不可约；保存预约时地点快照，变更需人工通知 |
| 设备 | 品牌必填并支持手填，型号选填；仅笔记本询问液金，笔记本＋Dell 显示选填 G15 问题；在保必答，均支持「是／否／不清楚」 |
| 故障与联系 | 故障单选，「其他」须补充说明；姓名、学号、学院和 QQ／微信二选一账号必填，邮箱选填；QQ 为首位非 0 的 5～12 位数字，学院不按校区过滤，隐藏字段不提交 |
| 协议 | 提交前同意协议并独立手写签名；阅读不自动同意，取消重签保留原签名；免费维修，配件自备，普通硅脂由中心提供 |
| 照片 | 故障照片选填，最多 4 张 JPG／PNG／WebP，单张 ≤2 MiB、最长边 2560 px；本机压缩，预约成功后逐张上传，失败可重试或补传，保留 180 天 |

填写分为到场时间、设备与联系、核对与签名三步，校区和时段不预选。时间或地点失效时返回选择页并保留其他输入。草稿在当前会话保存约两小时，恢复须确认并重新选择照片、同意协议和签名。超长输入保留原文并阻止提交，修改后清除提示。

创建请求携带 `Idempotency-Key`（32 字节随机值的 43 字符 base64url 编码）；同键重试返回原预约，同键不同内容拒绝。结果不明时通过 `/api/booking-attempts/resolve` 核实并保留原键。

新预约编号为 `reserve{校区代码}{预约日期YYYYMMDD}-{序号}`，全流程复用。历史编号和维修编号查询别名保留。

## 状态与现场维修

| 状态 | 数据库值 | 操作 |
| --- | --- | --- |
| 已预约 | `booked` | 学生可取消；工作人员核验并上传设备照片后接单 |
| 维修中 | `in_progress` | 当前维修人员填写结果并完成，不自动逾期 |
| 已完成 | `completed` | 必须记录说明和结果：修复成功、未修复或无需维修 |
| 已取消 | `cancelled` | 维修结果为空 |
| 已逾期 | `expired` | 有效期结束且未记录维修开始，维修结果为空 |

工作人员签到码用于到岗，客户维修码用于查单核验。编号尾号搜索至少两位且仅查当天，完整编号可跨日期查询；搜索只返回权限范围内的设备摘要。核验和接单须上传两张不同的设备正反面照片，每张 ≤2 MiB，保留 180 天；预览不改变状态。

每个成员使用一个登录账号，同时最多一张维修中工单。现场登记不占线上容量，每人最多一条待签到记录，当日 20:45 起不可新建。接单依赖维修角色、有效工作资格和现场条件；转派或纠错恢复为维修中时，接手人仍须满足这些要求及校区范围、空闲状态。已有本人维修可跨日完成。

预约纠错使用 `action=correct`。截止后恢复预约须填写原因并指定未来截止时间，重新校验容量、清空维修记录并重新核验拍照。历史缺失结果的 `legacy_unknown` 不计入修复成功率。

## 成员、账号与激活

成员身份、组织任职、工作资格、管理授权和登录账号分别保存。账号基础类型保留登录安全等级，普通业务请求统一由有效角色授权及对象范围决定。所属校区不自动授权，签到不扩大权限。详见 [身份映射](architecture/identity-mapping.md) 和 [授权规则](architecture/authorization.md)。

`root001`、`root002` 为受保护最高权限账号，仅本人验证旧密码后改密。账号管理受 `accounts.manage` 和校区范围约束。负责人可管理其他普通业务账号，禁止自行提权、越校区授权、修改受保护账号或授予系统级权限。

`repair_lead` 是部长及以上的长期业务管理角色，在授权校区内管理预约、纠错转派、统计、配置、排班、考勤、账号、成员、普通业务角色及工作资格，管理不依赖当日值班或签到。它不授予维修资格；实际接单仍需维修角色、维修／交流资格、到岗状态及工作窗口。排班只安排已有负责人，不授予长期角色，也不使用独立 `campus_admin`。

部员通过 `/staff/?activate=1` 申请并等待授权人员核验批准。普通加入名单仅邀请 `technician`；白名单 CSV 每次最多 200 条，必含 `studentId`，可选 `expectedName`、`expectedRole`、`authorizedCampuses`（多校区以 `|` 分隔）。重复学号或格式错误整批拒绝，已有记录跳过；普通白名单禁止 `expectedRole=admin`。

管理员邀请通过成员导入，必须明确填写 `accountRole=admin`、有效 `roleCodes` 和非空 `authorizedCampuses`；部门与工作资格按实际情况填写，可留空。已有管理员邀请也须具备明确成员授权，审批失败保留待审核申请且不生成账号。

工作人员 JWT 有效期 8 小时，退出、改密、停用或权限变化后撤销。学生私人凭证通过 URL fragment 携带，API 使用 `X-Appointment-Token`；编号、学号和维修二维码不能替代私人凭证。补发凭证须核验身份，旧凭证立即失效。

## 排班与收集

维修、办公采用“发布收集 → 整周填报 → 结束收集 → 自动排班 → 人工调整 → 检查发布 → 修订”。任务按岗位、校区、部门和工作周确定范围；管理授权必须覆盖任务的每一组范围，不能拼接不同授权。成员参加资格按班次日期的有效任职与工作资格判断，管理操作使用当前授权。

维修默认每日每校区一名负责人、至少 N 名普通人员，允许超过 N；办公按每日目标安排，均衡周内次数，每人每天最多一班。人数需求在任务内逐日、逐校区配置。办公负责人可在明确授权范围内管理维修排班，此权限不授予维修资格或现场转派能力。交流人员可签到接单，不参加维修收集和换班。

成员提交完整两小时班次或整周无法参加。循环收集只发布一次，结束后开放下一周；打开任务时解析当前周，不依赖 cron，不补建长期无人访问期间的全部周次。历史周补填不倒退当前周，也不重复推进。自动延续采用截止时有效的个人偏好，手动提交优先；截止后开启的偏好不回填过去，关闭偏好不删除已有提交。

人工移动只改变选中的原班次，额外安排保留其他班次。超出原填报须确认并记录覆盖，原始填报不变；锁定作用于具体班次。缺额、负责人数量及周内次数等业务偏差可逐项确认、填写原因后发布，确认绑定草稿版本与当前事实。资格、授权、实际时间冲突及受保护班次不可绕过。

修订从当前已发布班表复制，新稿发布前原班表持续有效。已签到、过去日期和暂停日期的已发布安排受保护，请假换班及历史关联保留。请假审批不伪造到岗；换班接受发布关联修订并重新校验双方资格、范围、请假、时间冲突和负责人覆盖。

## 考勤与暂停日期

普通维修及交流人员可在有效范围内扫码签到，未排班人员标记为非排班到岗；有效负责人可在授权校区自行签到，当天排班的办公人员也可直接签到。签到去重与历史修正规则见 [签到策略](architecture/attendance-policies.md)。

暂停日期按校区控制：阻止新预约、现场登记、开始维修及全部值班签到（含补录），填报和自动排班跳过该日。既有预约、已发布班次及考勤保留，已有维修可继续完成；恢复后沿用原容量。

按周核算每成员每周一行，先按授权范围过滤，再合并校区。实际签到与核算次数分别展示；“仅计首次有效签到”和“负责人每周计一次”独立、默认关闭。负责人按有效授权区间计周、兼任去重，授权服务日整周暂停计零；原签到事实不改写，预览和 CSV 使用同一算法。

页面隐藏时暂停轮询；打开扫描器启动摄像头，识别、关闭、切页、隐藏或离开时释放，返回页面不自动重启。附件均通过鉴权 API 访问，工作人员通用附件上限 5 MiB。
