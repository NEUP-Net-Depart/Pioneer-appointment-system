# 业务规则与权限

先锋网络中心硬件部为南湖、浑南校区提供免费维修，配件和耗材由机主自备。技术入口见 [README](../README.md)，部署和备份见 [运维文档](operations.md)。

## 预约规则

| 项目 | 当前规则 |
|---|---|
| 入口 | 访客免注册；浏览器自动保存预约凭证；凭私人链接跨设备访问 |
| 日期 | `Asia/Shanghai`，今天至第 3 天（含两端），仅周一至周四 |
| 时段与容量 | 19:00–20:00、20:00–21:00；管理员按授权校区、时段分别设置人数，默认 10 人；所有可预约日期共用配置 |
| 暂停与下调 | 人数为 0 暂停新增预约；低于已有预约数时不撤销原预约，已有预约仍可查询、取消、签到和维修 |
| 重复预约 | 同一学生同日同时段只能有一个占名额预约，跨校区也受限 |
| 名额释放 | 仅 `completed` 且结果为 `cancelled` 的预约释放名额；已完成维修和未到场仍占当日名额，恢复已取消的预约需检查实时容量 |
| 访客取消 | 仅可取消自己的 `booked` 预约 |
| 预约单号 | `reserve{校区代码}{提交当天YYYYMMDD}-{序号}`，按校区和提交日独立递增，至少两位序号 |
| 维修单号 | `{校区代码}{结束当天YYYYMMDD}-{序号}`，按校区和实际结束日独立递增，绝不继承预约单号；南湖 `0`、浑南 `1` |
| 协议签名 | 点击同意协议弹出手写板，完整签名确认后才能提交；支持鼠标、触屏、触控笔 |
| 签到照片 | 本次签到人必须上传电脑正、反两面图片，全部保存后才进入维修中；图片沿用附件大小和保留期限 |
| 附件 | JPG、PNG、WEBP、PDF、UTF-8 TXT，单文件最多 5 MB，自上传起保留 180 天 |

预约收集学号、姓名、校区、联系方式、设备和故障信息、日期时段及协议记录。QQ/微信必填；手机号、学院/专业、序列号、故障描述和备注等选填，完整字段见 [输入校验](../src/lib/validation.js)。预约选择器首次加载名额后，每 30 秒刷新当前校区可选日期的名额，并在选择校区、日期或时段时刷新；隐藏标签页时暂停，恢复可见时立即读取。已有请求进行中时跳过定时刷新，避免打断选择确认。个人预约的排队信息仍每 30 秒刷新，隐藏标签页时暂停。

管理员在工作人员端“个人设置 → 预约人数设置”中逐项保存非负整数人数。自动刷新保留未保存的输入，并发修改冲突时需重新读取配置。学生端按各时段显示剩余人数，最低为 0；暂停或满额时不可选择，已选时段失效时清空选择。

学生端顶部统一选择校区、日期和时段：默认展示南湖校区，日期卡片合计未结束时段的剩余人数，点击日期展开时段选择。仅显示预约范围内的服务日，已结束的时段及全天已结束的日期不显示。顶部校区按钮与预约表单的校区字段双向同步，切换校区后清空已选时段。日期和时段沿用原提交字段，表单不再重复提供选择器；名额读取失败时可手动重试，失败、满额或暂停的日期及时段不可选择。选择时段后先读取最新名额，确认成功后才选中；读取期间不可提交。选择不锁定名额，提交时由 D1 原子检查容量，满额或暂停会拒绝写入；前端提示原因并刷新名额、清空失效时段，保留表单和签名供用户重新选择。

事件时间保存为 UTC ISO，业务日期按上海时区计算。

名额首次读取或切换到未缓存校区时显示“剩余 0 名”，0 为加载占位，不代表已确认的名额；读取完成后以约 400ms 的竖向数字滚动切换到真实人数，标记及内部数字区域的宽高保持固定，仅数字滚动，位数变化不会移动“剩余”和“名”。按校区和日期在当前页面内存中保留已读取名额及对应更新时间，切换校区或日期时优先显示对应缓存，缓存数值与当前显示不同则播放数字滚动；过期日期缓存自动清理。刷新时保留已有名额和更新时间，仅当显示数值变化时播放滚动，最新数值与缓存相同则不重启动画；失败、暂停和满额显示明确状态。动画仅用于显示，可选状态和提交校验直接采用接口真实数据，屏幕阅读器立即获得最终人数；系统开启减少动态效果时直接显示最终人数。加载中仍禁用选择和提交，但不降低正常选项透明度，避免刷新时文字、占位宽度和明暗闪动。

预约选择器在手机、平板和桌面上统一采用异形日期按钮与横向长条时段，每个时段单独一行，左侧为时间、右侧为剩余名额与选择标记。窄屏按日期容器实际宽度自动调整日期字号，分区高度在 256–308px 范围内缩放；手机与桌面所有日期分区的星期与日期间距为 6px、日期与余量间距至少 10px；底部三角区域的余量与底边至少保持 14px 留白。手机端选中勾号紧跟星期文字，避免斜边裁切。较矮屏幕可正常滚动查看时段，选择操作不自动滚动。选择校区或日期不会主动滚动页面。900px 及以上的桌面屏幕采用等宽等高的左右两区，标题、说明、选项区域上下边界对齐：左侧采用异形日期按钮，1 天为大号倾斜日期与右下角余量、2 天用斜线分区、3 天用 Y 形分区、4 天用 X 形分区并按顺时针排列；各区域独立可点击，键盘聚焦清晰可见，选择区高度不随日期数量变化；右侧时段每项独占一行。日期选中态在桌面和手机均采用深色背景，时段采用浅绿背景、绿色边框与勾选。未选择日期时显示操作提示，并按当前实际可选时段数量预留列表高度，2/4 个时段展开时容器高度不变；中等屏幕采用上下排列，手机保留紧凑长条。剩余人数标记宽度固定，总容量放在下方作为次要信息。后续拆分为 4 个时段时沿用四行列表，实际开放时段与接口仍采用现有配置。

本地布局调试运行 `npm run preview:booking-layout`，打开 `http://127.0.0.1:8790/`，可实时模拟周一至周日，日期沿用真实预约规则（周五仅下周一、周六下周一和周二、周日下周一至周三），切换 2/4 个时段、手机和桌面比例预设，或自定义屏幕宽高。可按校区、所有日期或具体日期调整各时段总名额和剩余人数，具体日期配置优先；总名额为 0 模拟暂停，剩余为 0 模拟满额。修改配置不重载预约页面，保留已填信息和仍有效的选择，已选时段变满时自动取消选择。调试页使用独立的模拟时间和名额，并禁用提交；调试脚本不进入构建产物，不改变预约接口或真实数据。浏览器回归检查运行 `npm run test:booking-layout`（需安装 Playwright Chromium）。

## 角色与权限

| 角色 | 权限 |
|---|---|
| `technician` 维修人员 | 仅查看授权校区的待接单摘要和本人订单；接单后才能读详情与附件，不可转派 |
| `admin` 管理者 | 管理授权校区内的预约、时段人数配置、审核、派单、调整状态、统计及导出；管理维修人员账号 |
| `superadmin` 最高权限者 | 继承管理者权限，可调整低级账号角色，包括授予或收回管理者权限 |

管理者和最高权限者只能编辑、启停或重置密码低于自身且非保护的账号；停用账号保留维修历史，不提供删除账号接口。除 `root001`、`root002` 外，工作人员账号为 6–20 位数字学号。两个 root 受保护，管理 API 不可修改；本人可以验证当前密码后在个人设置中改密。

## 状态与统计

新预约进入 `booked`（已预约），工作人员点击签到后上传正反面照片，确认后记录当前登录人员和服务端开始时间，进入 `in_progress`（维修中）。填写结果与维修说明后进入 `completed`（已结束），记录结束时间并原子分配独立维修单号。结果包括 `repaired`（修复成功）、`unrepaired`（无法维修）、`not_needed`（无需维修）；取消和未到场也归入已结束，但结果为 `cancelled` / `no_show`，不生成维修单号。预约当天 21:30 后仍未签到的记录自动结束为未到场。

例如预约单 `reserve020251001-08` 在 10 月 2 日成为南湖当天第 1 张结束的维修单，则维修单号为 `020251002-01`，原预约单号和私人查询链接继续有效。两个序列互不继承；并发结束按数据库提交顺序分配编号。维修单号首次生成后保留，管理员纠错或重新结束不会重复分配或回收编号。升级前的历史预约编号不改写，避免破坏已有链接、附件及凭证关联。

维修人员按 [状态流转规则](../src/services/appointments.js) 操作；并发签到和更新通过 D1 revision 检查。管理员不能以纠错直接跳过首次签到拍照。统计支持指定日期或最近 7 天、30 天、全部记录，包含校区、故障和维修人员工作量；已结束中的维修结果与取消、未到场分别统计。工作人员列表、详情、学生查询和 CSV 同时展示预约单号与已生成的维修单号。

## 隐私与协议

- 密码使用 scrypt 哈希，联系方式使用 AES-256-GCM 加密。JWT 有效期 8 小时，工作人员会话存于 sessionStorage；退出、改密、停用、角色或授权校区调整会撤销旧会话。
- 服务端逐次校验账号、角色和对象权限。限流记录存于 D1，按 Cloudflare IP 的 HMAC 值计数，具体额度见 [限流服务](../src/services/rate-limits.js)。附件校验 MIME 和文件签名，仅通过鉴权 API 获取。
- 提交前同意免责协议并手写本人姓名（取消签名不会视为同意）：免费自愿、尽力维修但不保证修复、数据损失由机主承担、配件自备、在保优先官方售后。机主应先备份数据并遵守现场秩序；维修人员不得翻阅个人文件或聊天记录。协议正文见 [用户页面](../frontend/user/index.html)。

权限检查集中在 src/services/permissions.js。所属校区不推导权限；调整授权校区撤销所有旧会话。维修人员对未接单摘要的姓名、学号搜索也受限制，不能通过筛选推断未授权隐私。个人设置支持本人改密和撤销所有会话。
