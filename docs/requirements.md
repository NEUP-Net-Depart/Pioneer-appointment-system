# 业务规则与权限

开发入口见 [README](../README.md)，发布与回退见 [部署运维](operations.md)。字段及长度限制以 [输入校验](../src/lib/validation.js) 为准。

## 预约

| 项目 | 规则 |
|---|---|
| 访问 | 学生免注册；查询、取消、个人排队及附件须使用私人凭证 |
| 时间 | `Asia/Shanghai`，今天至第 3 天，仅周一至周四；19:00–21:00 分为四个半小时段（19:00–19:30、19:30–20:00、20:00–20:30、20:30–21:00） |
| 容量 | 按授权校区、时段设置，默认 10 人，所有日期共用；0 暂停新增，下调不撤销已有预约 |
| 名额 | 同一学生同日同时段不能重复占位，跨校区也受限；仅取消释放名额，恢复须重查容量 |
| 取消 | 学生只能取消自己的 `booked` 预约 |
| 编号 | `reserve{校区代码}{YYYYMMDD}-{序号}`；南湖 0、浑南 1，按校区和预约日期递增，两个时段共用、不回收 |
| 协议 | 提交前同意协议并手写本人姓名；免费维修，配件自备，普通硅脂由中心提供 |
| 附件 | JPG、PNG、WEBP、PDF、UTF-8 TXT，单文件最多 5 MB，保留 180 天 |

名额和排队信息每 30 秒刷新，页面隐藏时暂停轮询；时段失效保留已填内容并要求重选，服务端在提交时检查容量。新预约接口只接受四个半小时段，旧小时段仅作为历史数据库记录保留，不再出现在页面或新预约参数中。完整协议见 [用户页面](../frontend/user/index.html)。

## 扫码维修

维修人员登录后进入独立工作台，改密、会话管理和退出位于个人中心；管理员保留后台，可进入工作台并返回管理界面。

流程：扫码或输入编号 → 查看设备 → 上传两张不同的正反面照片并签到 → 维修 → 填写结果 → 返回扫码。

- 二维码为编号加 12 位 HMAC 校验码，不含学生私人凭证。仅授权工作人员可解析；扫码只定位，学生无需现场身份认证。
- 扫码成功停止摄像头；支持相册识别、手动编号，以及设备支持时的手电筒和镜头切换。
- 刷新或重新登录优先恢复本人的进行中工单；草稿和已上传照片 ID 按账号保存在本机。断网或提交结果不明时可重试或重新读取工单，同内容重试不重复签到、结束。
- 每人同时只能有一张进行中工单，新旧后台和管理员均受约束；已有历史冲突须逐张处理完才能接新单。
- 临时登记仅工作人员可用，复用拍照签到流程；不受时段限制、不占线上名额。重试不重复创建；同一维修人员只保留一条待签到记录，创建者可主动取消。

状态为 `booked` → `in_progress` → `completed`。签到记录负责人和开始时间；结束须填写说明及 `repaired`、`unrepaired` 或 `not_needed`。取消、未到场、过期结果分别为 `cancelled`、`no_show`、`expired`；线上预约和当天未签到的临时登记在 21:30 后自动结束。统计区分维修、取消、未到场和过期。

## 角色与激活

| 角色 | 权限 |
|---|---|
| `technician` | 授权校区的待接单设备摘要及本人工单；签到后读取详情、附件，不可转派 |
| `admin` | 授权校区的预约、维修、容量、审核、转派、纠错、统计、导出及维修人员账号管理 |
| `superadmin` | 继承管理员权限，可管理低级账号的管理员权限 |

所属校区不自动授予访问权限。只能管理低于自身角色、全部授权校区均在自身范围内且非保护的账号；停用保留历史，不删除账号。`root001`、`root002` 为受保护的 superadmin，管理 API 不可修改，本人可验证旧密码后改密。

激活流程：管理员导入白名单 → 部员在 `/staff/?activate=1` 填写学号、姓名、所属校区并设密 → 管理员人工核验后审核 → 本人使用自设密码登录。

CSV 必含 `studentId`，可选 `expectedName`、`expectedRole`、`authorizedCampuses`（多校区用 `|` 分隔）；缺省角色和校区使用导入表单值。单次最多 200 条，格式错误或重复学号整批失败，已有记录跳过。普通管理员只能导入、审核维修人员，superadmin 可处理管理员。待审不能登录；拒绝后可重申，撤销资格同时拒绝待审申请。

## 凭证与安全

学生私人链接用 URL fragment 携带凭证，打开后移除；API 使用 `X-Appointment-Token`，不得放入 query。编号、学号或维修二维码不能替代私人凭证。浏览器清理可能丢失凭证，私人链接勿转发。

凭证遗失由管理员核验本人身份，调用 `POST /api/appointments/:id/credential` 提交 `identityVerified=true` 和至少 8 字的说明；新凭证只返回一次，旧凭证立即失效。激活申请查询须持浏览器保存的 `X-Activation-Receipt`；遗失或被冒用时联系管理员，不凭学号放行。

工作人员 JWT 有效期 8 小时，保存在 sessionStorage；退出、改密、停用及角色或授权变更撤销旧会话。服务端逐次校验角色、校区与工单权限，附件校验 MIME 和文件签名。加密与持久化约束见 [数据模型](data-model.md)。
