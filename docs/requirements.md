# 业务规则与权限

先锋网络中心硬件部为南湖、浑南校区提供免费维修，配件及耗材由机主自备，清灰换硅脂提供普通硅脂。开发入口见 [README](../README.md)，配置与回退见 [部署运维](operations.md)。

## 预约规则

| 项目 | 规则 |
|---|---|
| 入口 | 学生免注册；浏览器保存预约凭证，私人链接可跨设备访问 |
| 日期与时段 | 上海时区，今天至第 3 天（含两端），仅周一至周四；19:00–20:00、20:00–21:00 |
| 容量 | 管理员在“个人设置 → 预约人数设置”按授权校区、时段设置非负整数，默认 10 人，所有预约日期共用配置 |
| 暂停与下调 | 0 人暂停新增；下调不撤销已有预约，查询、取消、签到、维修仍可继续 |
| 重复与释放 | 同一学生同日同时段不可重复占名额，跨校区也受限；仅取消释放名额，恢复取消记录须重新检查容量 |
| 取消 | 学生只能取消自己的 `booked` 预约 |
| 编号 | `reserve{校区代码}{YYYYMMDD}-{序号}`，南湖 `0`、浑南 `1`；按校区与预约日期递增，至少两位，两个时段共用、不回收 |
| 签名与照片 | 同意协议并完成手写签名后提交；签到由本次工作人员上传两张不同的电脑正反面照片 |
| 附件 | JPG、PNG、WEBP、PDF、UTF-8 TXT，单文件最多 5 MB，自上传起保留 180 天 |

预约收集学号、姓名、校区、QQ/微信、设备及故障信息、日期时段和协议签名；手机号、学院/专业、序列号、故障描述、备注等选填。字段与长度限制以 [输入校验](../src/lib/validation.js) 为准。名额和排队信息每 30 秒刷新，隐藏页面时暂停；时段失效保留已填内容并要求重选，提交时由服务端原子检查容量。事件时间保存为 UTC ISO，业务日期按 `Asia/Shanghai` 计算。

## 扫码维修与状态

维修人员默认进入扫码工作台，仅保留扫码、个人设置和退出；管理员保留完整后台，增加“扫码维修”入口。流程为：扫码 → 查看设备 → 上传正反面照片并签到 → 维修 → 填写结果 → 返回扫码。

- 二维码为预约编号加 12 位 HMAC 校验码，例如 `reserve020261013-01.012345abcdef`，不含学生私人凭证。仅登录工作人员可解析，仍受校区和工单权限约束；扫码只定位，不自动签到，学生无需现场身份认证。
- 扫码成功后停止摄像头；支持图片识别、手动输入编号，以及设备支持时的手电筒和镜头切换。摄像头需要 HTTPS 或本地可信源与浏览器授权。
- 刷新或重新登录恢复服务器上的本人进行中工单；维修草稿和已上传照片 ID 按账号保存在本机，不跨设备同步。断网或提交结果不明时可重试或“重新读取当前工单”，同内容重试不会重复签到或结束。
- 每人同时只允许一张进行中工单，旧后台和管理员操作也受约束。升级前已有多张的账号保留历史，逐张处理完后才能接新单。
- “临时维修登记”仅工作人员可用，保留原预约信息及机主签名，随后走相同照片签到流程；登记重试不会重复创建。现场记录不受预约时段限制、不占线上名额、不自动判为未到场，保留在管理、统计及导出中；待签到记录可由管理员取消。

状态依次为 `booked`（已预约）→ `in_progress`（维修中）→ `completed`（已结束）。签到由服务端记录负责人和开始时间；结束须填写维修说明和结果：`repaired`、`unrepaired`、`not_needed`。取消和未到场同属已结束，结果为 `cancelled` / `no_show`；线上预约当天 21:30 后仍未签到可被自动结束为未到场。

管理员不能通过纠错跳过首次拍照签到；并发更新校验 revision。全流程复用预约编号，不生成新维修编号；历史预约号和维修号保留，可查询和导出。统计支持指定日期、最近 7 天、30 天和全部记录，维修结果与取消、未到场分开统计。

## 角色与账号

| 角色 | 权限 |
|---|---|
| `technician` | 授权校区的待接单设备摘要及本人订单；签到后读取详情与附件，不可转派 |
| `admin` | 授权校区内的预约、扫码维修、容量、审核、派单、纠错、统计、导出及维修人员账号管理 |
| `superadmin` | 继承管理员权限，可授予或收回低级账号的管理员权限 |

所属校区不自动产生权限，访问以授权校区为准。账号管理仅允许操作低于自身角色、全部授权校区均在自身范围内且非保护的账号。停用保留历史，不提供删除账号 API。普通账号为 6–20 位数字学号；`root001`、`root002` 为受保护的 superadmin，管理 API 不可修改，本人可验证旧密码后改密。

管理员导入白名单 CSV 后发送 `/staff/?activate=1`，部员填写学号、姓名、所属校区、核验联系方式并自行设密。CSV 必含 `studentId`，可选 `expectedName`、`expectedRole`（technician/admin）、`authorizedCampuses`（多个校区以 `|` 分隔）；省略角色或授权列时使用导入表单默认值。支持 UTF-8 BOM、CRLF 和标准引号，单次最多 200 条；错误或重复学号使整批失败，已有资格或账号跳过、不覆盖。

角色和授权只来自管理员名单；普通管理员只能导入/审核维修人员，superadmin 可处理管理员。待审申请不能登录，同一学号最多一条待审申请。管理员须人工核验身份，批量通过时勾选已核验；审核说明选填、最多 300 字。通过时原子创建账号与授权；拒绝保留审核记录并清除密码哈希，可重新申请；撤销资格同时拒绝待审申请。

申请回执由浏览器保存，查询使用 `X-Activation-Receipt`，不能凭学号查看。回执遗失或申请被冒用时联系管理员；冒用申请先拒绝再由本人重申，不按白名单自动批准。审批通过后直接使用自设密码登录。

## 学生凭证与隐私

学生访问凭证为独立的 32 字节随机值，创建时仅返回一次，D1 只保存 SHA-256。浏览器 localStorage 保存编号和凭证；私人链接用 URL fragment 携带凭证，打开后从地址栏移除，请求使用 `X-Appointment-Token`，不得放入 API query。查询、取消、个人排队及附件均须有效凭证，编号或学号不能代替凭证，历史编号同样适用。

私人链接勿转发；清理浏览器数据可能丢失凭证，系统不按学号自动找回。遗失后由管理员对照本人学生证及预约资料人工核验，在 `POST /api/appointments/:id/credential` 提交 `identityVerified=true` 和至少 8 字的核验说明；新凭证仅返回一次，交给核验通过的学生，旧凭证立即失效。

密码使用 scrypt，联系方式使用 AES-256-GCM。工作人员 JWT 有效期 8 小时，保存在 sessionStorage；退出、改密、停用、角色或授权校区变更撤销旧会话。服务端逐次校验角色、校区与对象权限，附件检查 MIME 和文件签名，限流按 Cloudflare IP 的 HMAC 值记录。实现见 [权限服务](../src/services/permissions.js) 和 [限流服务](../src/services/rate-limits.js)。

机主提交前须同意协议并手写本人姓名：免费自愿、尽力维修但不保证修复、数据损失由机主承担、配件自备、在保优先官方售后；应先备份数据并遵守现场秩序，维修人员不得翻阅个人文件或聊天记录。协议正文见 [用户页面](../frontend/user/index.html)。
