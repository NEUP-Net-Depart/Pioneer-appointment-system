# 需求与设计

这份文件记录业务背景、原始需求和后续规划。当前可运行代码、准确的接口、部署方式和安全约束以根目录 [README.md](../README.md) 为准。

## 目标

将访客的免费维修预约、排队、接单、维修记录和统计集中到一个系统中，支持南湖、浑南两个校区。系统不收费，配件和耗材由机主自行准备。

## 账号层级

```text
学生 student
  ↓
维修人员 technician
  ↓
管理者 admin
  ↓
最高权限者 superadmin
```

普通用户无需账号即可预约。维修人员、管理者和最高权限者使用统一的账号密码登录；工作人员账号使用本人学号，基础角色可再升级为维修人员或管理者。`root001` 和 `root002` 是两个受保护的最高权限账号。

账号保存于 D1；除两个 root 账号外，新增账号统一为 6–20 位数字学号。

## 核心流程

```text
直接填写维修单 → 阅读免责协议 → 提交预约并获得预约编号
→ 管理者审核/待接单 → 维修人员接单 → 维修中
→ 已完成/无法维修/爽约 → 预约编号 + 学号查询进度 → 管理者统计导出
```

## 预约规则

| 项目 | 规则 |
|---|---|
| 服务时间 | 周一至周四 19:00–21:00 |
| 时间段 | 19:00–20:00、20:00–21:00 |
| 可预约日期 | 今天起 3 天内的服务日 |
| 容量 | 每校区、每时段默认 20 人 |
| 校区 | 南湖、浑南独立计数 |
| 重复预约 | 同一学生同一天同一时段只能有一个占用名额的预约（取消、爽约不占名额） |
| 取消 | 访客使用预约编号 + 学号只能取消自己的待审核/待接单预约；管理者可处理全部预约 |
| 费用 | 免费，不涉及支付 |

预约编号格式为 `{校区代码}{YYYYMMDD}-{序号}`，南湖代码为 `0`，浑南代码为 `1`。

## 访客预约字段

- 学号、姓名、校区；手机号选填。
- 学院/专业、QQ/微信，其中 QQ/微信为必填联系方式。
- 设备类型、品牌、型号、序列号、是否在保。
- 故障类型、是否进液/摔过；故障描述选填。
- 预约日期、时段、备注、免责协议版本和同意时间。

访客使用预约编号 + 学号查看自己的预约、实时排队位置和处理状态；手机号和备用联系方式需要加密保存。预约可选上传故障照片或相关文件，支持 JPG、PNG、WEBP、PDF、TXT，单个文件不超过 5 MB；访客只能查看自己预约的附件，维修人员和管理员可在工作台查看对应预约附件。

## 维修人员端

- 查看预约列表并按校区、日期、状态筛选。
- 抢待接单预约，接单后只能处理自己的预约。
- 更新为维修中、已完成、无法维修或爽约。
- 填写检测、维修、更换部件和烤机记录。

## 管理者端

- 查看和处理所有预约，审核、派单、调整状态和导出 CSV。
- 管理低于自身权限的账号，停用、启用、重置密码。
- 将学生提升为维修人员。
- 删除低于自身权限的账号，历史预约保留。
- 查看指定日期、日期范围、校区、故障类型和维修人员工作量统计。

## 最高权限者端

- 继承管理者全部权限。
- 将维修人员提升为管理者，或收回管理者权限。
- 删除低级维修人员或管理者账号：移除登录账号，历史预约保留。
- 不能停用、删除、重置或降级 `root001`、`root002`。

## 状态

| 状态 | 含义 |
|---|---|
| `pending` | 待审核 |
| `awaiting_claim` | 待接单 |
| `claimed` | 已接单 |
| `in_progress` | 维修中 |
| `completed` | 已完成 |
| `cancelled` | 已取消 |
| `no_show` | 爽约 |
| `no_repair` | 无法维修 |

故障分类统计只以 `completed` 记录为依据。

## 免责协议要点

1. 服务为免费、自愿的互助维修，不收取费用。
2. 维修人员尽力维修，但不保证一定修好。
3. 维修可能存在意外风险，数据损失由机主自行承担。
4. 配件和耗材由机主准备，不提供代购。
5. 在保设备建议优先联系官方售后。
6. 机主应提前备份重要数据并遵守现场秩序。

## 数据与安全要求

- 密码使用 scrypt 哈希，禁止明文保存。
- 联系方式使用 AES-256-GCM 加密，密钥由生产环境变量提供。
- 访客只能通过预约编号 + 学号读取自己的预约；维修人员只能处理自己接单的预约。
- 服务端必须重新执行角色、账号状态和对象归属校验。
- 使用 D1 migrations 管理 schema；数据库备份和 R2 对象备份分别管理。
- 生产环境启用 Pages HTTPS 和 Secrets，通过 D1 导出与 Time Travel 管理数据库恢复。
- 不收集身份证等与维修无关的信息。
