# 业务规则与权限

字段及长度限制以 [输入校验](../src/lib/validation.js) 为准，部署命令见 [部署运维](operations.md)。

## 预约

| 项目 | 规则 |
|---|---|
| 访问 | 学生免注册；查询、取消、个人排队及附件须使用私人凭证 |
| 时间 | `Asia/Shanghai`，今天至第 3 天，仅周一至周四；19:00–21:00 分为四个半小时段（19:00–19:30、19:30–20:00、20:00–20:30、20:30–21:00） |
| 容量 | 按校区、工作日和半小时时段配置，默认每段 5 人；日期首次预约后冻结，修改仅影响尚未预约的日期 |
| 名额 | 仅取消释放容量；取消和逾期均释放同学号同日同时段的唯一占位，跨校区也受限 |
| 取消 | 学生只能取消自己的 `booked` 预约 |
| 编号 | `reserve{校区代码}{YYYYMMDD}-{序号}`；南湖 0、浑南 1，所有时段共用序号、不回收 |
| 协议 | 提交前同意协议并手写签名；免费维修，配件自备，普通硅脂由中心提供 |
| 附件 | JPG、PNG、WEBP、PDF、UTF-8 TXT，单文件最多 5 MB，保留 180 天 |
| 签到照片 | 选择照片后自动压缩并上传，确认签到后才进入维修中；须由本次签到人上传正、反两面照片，每张最多 2 MB，保留 180 天 |

签到照片自动校正方向，最长边 2560 px，JPEG 初始质量 0.85，期望大小 1–1.5 MB，硬上限 2 MB。压缩失败须提示原因；支持 JPG、PNG、WebP 且不超过 2 MB 的原图可回退上传。无法转换的 HEIC/HEIF 须转为 JPG 或重新拍摄。

名额和排队信息每 30 秒刷新，页面隐藏时暂停轮询；时段失效保留已填内容并要求重选，服务端在提交时检查容量。新预约接口只接受四个半小时段，旧小时段仅作为历史数据库记录保留，不再出现在页面或新预约参数中。完整协议见 [用户页面](../frontend/user/index.html)。

维修地点按校区配置，仅最高管理员可修改授权校区的地点。预约选择、提交成功和“我的预约”显示最新配置；未配置时提示联系工作人员确认。

## 状态与逾期

| 状态 | 数据库值 | 含义 |
|---|---|---|
| 已预约 | `booked` | 等待维修 |
| 维修中 | `in_progress` | 已接单并开始维修 |
| 已完成 | `completed` | 维修结束，有明确结果 |
| 已取消 | `cancelled` | 主动取消 |
| 已逾期 | `expired` | 有效期限结束，未记录维修开始 |

完成维修须填写说明及 `repaired`、`unrepaired` 或 `not_needed`。取消直接提交 `status=cancelled`；取消和逾期的维修结果为空。`pending` 仅为已预约和维修中的组合筛选。

普通预约和临时登记默认在当日 21:30 到期；仅 `booked` 且未记录开始时间的工单自动逾期，维修中工单不自动逾期。不判断学生是否实际到场，也不提供到场确认操作。

> 预约时段已结束，本次预约未记录维修开始。如仍需维修，请重新预约或联系工作人员。

管理员使用 `action=correct` 纠错。截止后恢复为已预约，须填写 8–300 字 `correctionReason` 并指定未来的 `expiresAt`（含时区）。恢复校验容量，清空原人员、签到照片、维修记录及时间，并要求重新拍照签到；不能直接将未维修的终态工单改为维修中或已完成。

完成、取消、逾期分别统计，逾期率为逾期数 / 总数。历史缺失结果保留 `legacy_unknown`，不计入修复成功率分母，新请求不能填写此标记。

## 扫码维修

- 二维码仅含编号和 12 位 HMAC 校验码；授权工作人员可用扫码、相册或编号定位工单。
- 签到须上传两张不同的电脑正反面照片，记录负责人和开始时间；完成须填写结果和说明。
- 每人同时最多一张进行中工单。刷新或重新登录恢复本人工单，草稿和照片 ID 按账号保存在本机；相同签到、完成请求可安全重试。
- 临时登记仅工作人员可用，不占线上容量或排队；每人最多一条待签到记录，创建者可取消，当天 21:30 起不再新建。

## 角色与激活

| 角色 | 权限 |
|---|---|
| `technician` | 授权校区的待接单设备摘要及本人工单；签到后读取详情、附件，不可转派 |
| `admin` | 授权校区的预约、容量、激活审核、转派、纠错、统计、导出及维修人员账号管理 |
| `superadmin` | 继承管理员权限，可管理低级账号的管理员权限 |

所属校区不自动授予权限。账号管理限于角色低于本人、授权校区均在本人范围内且非保护的账号；停用保留历史。`root001`、`root002` 为受保护的 superadmin，仅本人可验证旧密码后改密。

部员须在白名单内，通过 `/staff/?activate=1` 申请并经管理员核验批准。CSV 必含 `studentId`，可选 `expectedName`、`expectedRole`、`authorizedCampuses`（多校区用 `|`）；单次最多 200 条，格式错误或重复学号整批失败，已有记录跳过。普通管理员仅审核维修人员；待审不可登录，拒绝可重申，撤销资格同时拒绝待审申请。

## 凭证与安全

私人链接用 URL fragment 携带凭证；API 使用 `X-Appointment-Token`，不得放入 query。编号、学号和维修二维码不能替代凭证。凭证遗失须由管理员核验身份后调用 `POST /api/appointments/:id/credential`，提交 `identityVerified=true` 和至少 8 字说明；新凭证仅返回一次，旧凭证立即失效。激活查询使用 `X-Activation-Receipt`。

工作人员 JWT 有效期 8 小时；退出、改密、停用及角色或授权变更撤销会话。附件校验 MIME 和文件签名，加密与持久化约束见 [数据模型](data-model.md)。
