# 业务规则与权限

本页记录当前业务规则。表单细节见 [学生配置](../shared/student-booking.js)，接口见 [平台契约](contracts/staff-platform.json)。业务日期均为 Asia/Shanghai。

## 预约与接收

学生免注册，以私人凭证查询和取消本人预约。各校区保留放号时间、周一至周四服务日、半小时时段和容量配置。新预约在所选时段结束前提交；已预约的工单在预约当天可以跨时段接收和接单，未接收的预约在次日零点过期。取消、已结束、已过期的工单不会因为日期相同被恢复。

线上预约严格限额，取消释放名额，完成和未到场的历史占用继续保留。同学号同日最多一个有效线上预约。工作人员现场登记独立记录来源、经办人、时间与请求键，不占线上名额；线上满额不阻止现场登记。容量更新不会取消或改写已有预约。

预约容量、放号时间、预约公告、暂停维修日期和维修地点统一由 `booking.manage` 管理。有效副部长、部长可管理所属校区；副站长、站长、副主席、主席及超级管理员可管理两校区，均不得超出账号当前授权校区。普通部员无此权限，任职变化自动生效，不授予系统设置权限。

学生按到场时间、设备与联系、核对与签名三步提交。型号可留空，联系方式及协议签名保留现有校验；设备资料在维修时复用，有误再改。学生故障照片选填，首次接收设备的正反面照片另行留证。重要公告确认版本、地点快照及私人凭证随预约保留。创建以 43 字符随机 Idempotency-Key 去重，响应丢失时查询同一次创建回执。

## 维修与返修

“今日工作”统一提供扫码、现场登记、查询、今日待接收、已接收待维修、本人维修、照片补传和签到。维修事务任职与硬件部人员均可在授权校区核对预约、拍照并选择“仅接收设备”；接收只保存接收人、时间及照片，工单保持 booked，主修为空。硬件部也可选择“接收并开始维修”，独立完成全流程。已接收工单持续显示在待维修区，包括往日接收的工单；硬件部成员确认接手后进入 in_progress，无需重复拍照。两种工作方式按实际操作自然衔接，不选择模式、不预分派。

维修准入依据当前有效硬件部任职（含交流维修）及授权校区。允许多单和跨日维修，不依赖独立维修资格、签到、排班、在岗状态和工作窗口。其他硬件部成员实际接到维修中的设备后自行确认交接，自动记录原主修、新主修和时间。资料完善、上传照片不改变主修。只记录主修和正式交接，不要求协助人员或独立统计填报；责任统计不代表全部实际劳动。

首次接收必须拍摄并尝试上传正反面照片。只有上传超时才出现“稍后补传”；继续接单后记录工单与经办人的待传标记。本人手动选择留存的接收原图补齐后清除标记，部分补齐仍保留。无跨页图片缓存、恢复、后台重试或上传队列。同一工单跨日或交接复用照片；新的到访工单重新留证。外观出现新变化可以补拍，但不能用维修后的照片冒充接收原图。补传不改变主修、结果或服务状态，待传记录在经办人的工单历史中持续可见。

结束服务填写一句内部说明，选择已解决、部分解决、未解决或无需维修。部分解决和未解决说明剩余问题，不要求完整过程报告或另写客户版说明。主状态与结果分离；结束时主修及校区内有管理身份的工作人员可以更正结果和说明，保留原值、操作者和时间，不改写责任历史。

普通部员不展示维修与交接操作历史、原始登记及协议证据，接口也不返回相关原始字段。负责人及系统管理员在授权校区内通过明确的查看入口读取；维修人员仍可查看当前接收人与主修，以及诊断、返修关联所需的历史维修结果。

原故障续修或复发通过新工单关联原单；已预约的关联现有预约，现场到访的登记新单。工作人员明确确认同一设备、同一故障，系统不凭学号自动关联。普通接单提示该客户已有维修历史，并提供原单结果、内部说明和历史入口，由工作人员确认是否关联。全新故障和未到场后重新登记都不计返修。没有已知到访就不创建待排期、待联系任务。旧申请只做一次性迁移，运行时无申请、审批、排期入口。

普通工作人员可按预约编号、学号、姓名及完整联系方式搜索授权校区内历史工单；联系方式仍为完整值精确匹配。单张详情可查看必要联系方式并自动记录访问审计，列表及搜索候选不带联系方式。学生端只返回服务结果及公开事实，当前单、关联单和历史单均不返回内部说明、内部人员信息和操作历史。联系方式更改的审计保存加密值。

## 身份和管理

人员档案、有效任职、账号与校区范围分开记录。部长、副部长可管理授权校区各部门资料、排班和考勤补记；站长、副站长、主席、副主席可管理全部校区。副部长及以上和超级管理员还可在当前授权校区内审核激活申请、管理激活资格及普通账号，沿用成员管理的任职判断。实际任职决定业务管理权限，系统设置、角色配置仍须独立授权。账号自提权、受保护账号修改和对象越权仍被拒绝。

新增人员默认建立待激活资格，未指定授权校区时使用所属校区，不要求额外勾选或点击资格配置项。已有明确撤销的资格保持撤销。具备资格不等于已创建账号，成员仍须自行设置密码、提交申请并经负责人审核。

有效硬件部正式或交流任职可接待和维修，有效维修事务任职可接待；维修事务与交流维修可以同时持有。办公室部门身份本身不再授予事务权限，不对存量办公室人员自动补授任职。后端按每次请求的当前全部有效任职与授权校区检查，其他部门的账号或系统角色不会自动取得接待或维修权限。查询和管理仍沿用各自权限。独立维修资格表和工作权限包已删除。成员可只建档案；登录激活仍需有效成员、核验批准与授权校区，不需要维修资格。

单人新增和 CSV 导入共用规则，保留逐人差异预览与并发检查。资料空白默认保留旧值；替换授权校区必须显式选择并通过对象权限检查。部门表与现有数据保留，仅提供只读查询，组织结构调整通过数据库迁移完成。受保护 root001/root002 不通过普通成员或角色接口修改。

## 排班与考勤

日常入口为「值班」：部长默认进入「今日值班」，另有「安排下周」「统计与历史」；参与值班的部员默认进入「我的值班」，先看今日、下次班次、签到和本月及累计志愿时长。普通网络部部员无需排班，不显示值班入口、页面或个人中心的今日排班，登录直接进入现场工作台；具有实际管理身份的人员保留管理入口。沿用工作校区，单校区用户无需选择，不向日常用户展示场次配置。

维修与办公新班次固定为19:00–21:00，签到窗口18:30–21:30。成员按星期、校区勾选整班空闲，通常安排持续沿用，临时变化只覆盖对应周，也可恢复沿用。旧时间窗口完整覆盖固定班次时显示为有空，部分覆盖提示重新选择，读取不改写原数据。既有特殊时段和班次 ID 保留，主动替换才使用固定时段。

自动建议共同编排当前校区周一至周四的维修与办公班表，跳过暂停日。办公候选只依据有效维修事务任职，包括负责人；交流维修本身不产生自动维修候选，交流维修与维修事务双任职依据后者进入办公候选。维修候选保留硬件部正式任职及跨校区负责人规则。候选均要求有效账号、校区授权和对应整班空闲，空闲可按授权校区填报。每校区每日争取一位实际有效的硬件部部长、副部长或站长、副站长、主席、副主席；其他部门部长及系统管理员标签本身不满足该负责人要求。先以最大匹配覆盖负责人，再按空闲较少优先、类型每日人数和校区每日总人数均衡安排其他成员。同样输入结果相同。手动安排及换班不新增任职限制。“办公班次”是工作名称，不更名为任职名称。

自动建议每人在全部校区、两类值班间每周最多一次，其他校区已有班次计入占用。手动重复安排允许作为例外发布，需显示提示并保留审计。无每日人数门槛；缺负责人、当天无人可排和未安排成员均说明原因。建议不写班表，重新生成只替换自动部分，保留发布及手动调整内容。两类班表同事务发布，检查版本、权限、人员有效性和时间冲突，幂等准备每日共用签到场次，但不生成签到事实。

请假直接登记，不需要批准或先找接替者。接替者确认即可转移班次，负责人可按线下协调结果直接调整。当前人员有效性、校区范围、班次版本和时间冲突在事务内检查。已请假与未登记请假在班表、考勤核查中分别显示。详见 [排班接口与结构](architecture/schedule.md)。

今日名单从有效班次出发关联请假、签到和核查结论，覆盖未签到人员，人数按成员去重。请假人员单列且排除应到，临时到场单列。开班前显示待签到，开班后突出未签到，不自动判定迟到或缺勤。部长在当日签到窗口内可对人员直接确认到场，服务端确定日期、时间和场次，同批写入签到、到场事件、操作者审计和幂等回执。扫码并发与重试保留首次事实。

现场签到码由负责人或有效维修事务人员在授权校区出示，不要求本人先签到。维修事务人员无论是否排班，均可在原签到时段内直接到岗签到。每人刷新仅替换本人的码，其他人的码继续有效。今日工作和个人中心顶部按服务端权限及当前校区、日期的真实考勤记录显示签到待办，签到成功后立即隐藏；我的值班复用相同规则。维修部员通过专用入口扫码签到，现有办公排班人员及负责人直接签到规则保留。工作人员只需签到一次，无需手动离岗或返回岗位。班次结束后部长可确认未到并撤销，结论保留版本和操作历史，不生成签到；后续真实到场优先显示。漏签补录与时间修正从人员行进入，服务端按人员、日期、校区解析场次，只填写实际时间与原因。历史补录不改变到场事件，暂停服务、越权和失效人员在提交事务内拒绝。签到和接单解耦。签到来源保存扫码签发人、直接签到或补记操作者，重复签到不覆盖首次来源，仅考勤管理范围内可见；未记录来源的历史数据不推断补填。

周报的实际次数、首次有效签到、负责人每周一次，月报的计数模式、小时换算和负责人合并继续沿用现有参数，个人时长与管理报表共用计算逻辑，先过滤访问范围再聚合。默认核算时长不生成虚假签到，维修数量和持续时间不作为出勤或志愿时长依据。暂停服务保留原业务事实，按原算法从有效服务日核算中排除。不新增4/16小时制度、月度封顶、结转或学期清零。

接收、接单、交接、结束和修改自动记录操作者与实际操作时间，字段修改保留前后值。原始预约、维修、照片、签到、人员和审计历史持续保留；历史未修复不能推断为部分解决或未解决，也不能补造历史协助或到岗事实。
