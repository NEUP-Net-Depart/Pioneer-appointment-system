# 业务规则与权限

本页记录当前业务规则。表单细节见 [学生配置](../shared/student-booking.js)，接口见 [平台契约](contracts/staff-platform.json)。业务日期均为 Asia/Shanghai。

## 预约与接收

学生免注册，在提交预约的浏览器中通过「我的预约」查询和取消本人预约。各校区保留放号时间、周一至周四服务日、半小时时段和容量配置。新预约在所选时段结束前提交；已预约的工单在预约当天可以跨时段接收和接单，未接收的预约在次日零点过期。取消、已结束、已过期的工单不会因为日期相同被恢复。

线上预约严格限额，取消释放名额，完成和未到场的历史占用继续保留。同学号同日最多一个有效线上预约。工作人员现场登记独立记录来源、经办人、时间与请求键，不占线上名额；线上满额不阻止现场登记。容量更新不会取消或改写已有预约。

预约容量、放号时间、预约公告、暂停维修日期和维修地点统一由 `booking.manage` 管理。有效副部长、部长可管理所属校区；副站长、站长、副主席、主席及超级管理员可管理两校区，均不得超出账号当前授权校区。普通部员无此权限，任职变化自动生效，不授予系统设置权限。

学生按到场时间、设备与联系、核对与签名三步提交。型号可留空，联系方式及协议签名保留现有校验；设备资料在维修时复用，有误再改。学生故障照片选填，首次接收设备的正反面照片另行留证。预约保留重要公告确认版本和地点快照。浏览器保存访问凭证，用于查看预约、上传附件和获取到场二维码。创建以 43 字符随机 Idempotency-Key 去重，响应丢失时查询同一次创建回执。

## 维修与返修

“今日工作”统一提供扫码、现场登记、查询、今日待接收、已接收待维修、本人维修、照片补传和签到。维修事务任职与硬件部人员均可在授权校区核对预约、拍照并选择“仅接收设备”；接收只保存接收人、时间及照片，工单保持 booked，主修为空。硬件部也可选择“接收并开始维修”，独立完成全流程。已接收工单持续显示在待维修区，包括往日接收的工单；硬件部成员确认接手后进入 in_progress，无需重复拍照。两种工作方式按实际操作自然衔接，不选择模式、不预分派。

维修准入依据当前有效硬件部任职（含交流维修）及授权校区。允许多单和跨日维修，不依赖独立维修资格、签到、排班、在岗状态和工作窗口。其他硬件部成员实际接到维修中的设备后自行确认交接，自动记录原主修、新主修和时间。资料完善、上传照片不改变主修。只记录主修和正式交接，不要求协助人员或独立统计填报；责任统计不代表全部实际劳动。

首次接收必须拍摄并尝试上传正反面照片。只有上传超时才出现“稍后补传”；继续接单后记录工单与经办人的待传标记。本人手动选择留存的接收原图补齐后清除标记，部分补齐仍保留。无跨页图片缓存、恢复、后台重试或上传队列。同一工单跨日或交接复用照片；新的到访工单重新留证。外观出现新变化可以补拍，但不能用维修后的照片冒充接收原图。补传不改变主修、结果或服务状态，待传记录在经办人的工单历史中持续可见。

接收正反面照片与补充照片共用拖拽、选择、预览和替换控件，取消文件选择不得关闭工单。整个上传框支持拖放，跨越图标、文字不视为离开上传区。维修信息与官方支持按用途分组，操作入口直接可见；同一时间只展开一个操作区，表单底部并排提供取消与保存。有未保存内容时，工单操作、页面切换和预约配置共用提醒窗口：右上角为“取消操作”，底部左侧红色“丢弃并继续”、右侧黑色“保存并继续”；取消提醒保留填写内容，保存失败不继续切换。

工单资料同时支持校对与补充。设备、故障和联系方式以预约表的字段与公共选项为准，液金仅在笔记本显示，Dell G15/G16 仅在 Dell 笔记本显示；现场登记沿用相同条件。序列号、进水、电话等额外资料集中于现场补充，登记备注沿用管理权限，学号与协议签名保持只读。修改复用现有工单字段、审计与操作回执，不新增数据库结构，仅提交实际变更；显式更换设备类型或品牌时清理不适用的液金或 Dell 系列值。

结束服务填写一句内部说明，选择已解决、部分解决、未解决或无需维修。部分解决和未解决说明剩余问题，不要求完整过程报告或另写客户版说明。主状态与结果分离；结束时主修及校区内有管理身份的工作人员可以更正结果和说明，保留原值、操作者和时间，不改写责任历史。

普通部员不展示维修与交接操作历史、原始登记及协议证据，接口也不返回相关原始字段。负责人及系统管理员在授权校区内通过明确的查看入口读取；维修人员仍可查看当前接收人与主修，以及诊断、返修关联所需的历史维修结果。

原故障续修或复发通过新工单关联原单；已预约的关联现有预约，现场到访的登记新单。工作人员明确确认同一设备、同一故障，系统不凭学号自动关联。普通接单提示该客户已有维修历史，并提供原单结果、内部说明和历史入口，由工作人员确认是否关联。全新故障和未到场后重新登记都不计返修。没有已知到访就不创建待排期、待联系任务。旧申请只做一次性迁移，运行时无申请、审批、排期入口。

普通工作人员可按预约编号、学号、姓名及完整联系方式搜索授权校区内历史工单；联系方式仍为完整值精确匹配。单张详情可查看必要联系方式并自动记录访问审计，列表及搜索候选不带联系方式。学生端只返回服务结果及公开事实，当前单、关联单和历史单均不返回内部说明、内部人员信息和操作历史。联系方式更改的审计保存加密值。

## 身份和管理

人员档案、有效任职、账号与校区范围分开记录。部长、副部长可管理授权校区各部门资料、排班和考勤补记；站长、副站长、主席、副主席可管理全部校区。副部长及以上和超级管理员还可在当前授权校区内审核激活申请、管理激活资格及普通账号，沿用成员管理的任职判断。实际任职决定业务管理权限，系统设置、角色配置仍须独立授权。账号自提权、受保护账号修改和对象越权仍被拒绝。

退休老登（`retired_elder`）是独立存储的特殊身份，不属于组织职位。仅超级管理员可在人员管理中手动授予或撤销，不按历史任职或离任自动授予。它拥有与设备服务站站长相同的双校区业务管理权限，不获得超级管理员专属系统权限；可以管理其他人的排班和考勤，本人不参与维修或办公排班、空闲填报和换班；可在授权校区正常扫码签到或自行签到，按现有计次、去重、暂停日期及小时换算规则累计有效签到产生的志愿时长，未签到不计时长，不因该身份享受负责人自动计入。考勤补记限制保持不变。授撤均审计并立即失效旧会话，保留原任职、签到和历史志愿时长。本次仅用于已无有效任职的老成员，不引入并存身份的优先级、互斥或转换规则。

新增人员默认建立待激活资格，未指定授权校区时使用所属校区，不要求额外勾选或点击资格配置项。已有明确撤销的资格保持撤销。具备资格不等于已创建账号，成员仍须自行设置密码、提交申请并经负责人审核。

有效硬件部正式或交流任职可接待和维修，有效维修事务任职可接待；维修事务与交流维修可以同时持有。办公室部门身份本身不再授予事务权限，不对存量办公室人员自动补授任职。后端按每次请求的当前全部有效任职与授权校区检查，其他部门的账号或系统角色不会自动取得接待或维修权限。查询和管理仍沿用各自权限。独立维修资格表和工作权限包已删除。成员可只建档案；登录激活仍需有效成员、核验批准与授权校区，不需要维修资格。

单人新增和 CSV 导入共用规则，保留逐人差异预览与并发检查。资料空白默认保留旧值；替换授权校区必须显式选择并通过对象权限检查。部门表与现有数据保留，仅提供只读查询，组织结构调整通过数据库迁移完成。受保护 root001/root002 不通过普通成员或角色接口修改。

## 排班与考勤

日常入口为「值班」：部长默认进入「今日值班」，另有「安排下周」「统计与历史」；参与值班的部员默认进入「我的值班」，先看今日、下次班次、签到和本月及累计志愿时长。普通网络部部员无需排班，不显示值班入口、页面或个人中心的今日排班，登录直接进入现场工作台；具有实际管理身份的人员保留管理入口。沿用工作校区，单校区用户无需选择，不向日常用户展示场次配置。

维修与办公新班次固定为19:00–21:00，签到窗口18:30–21:30。成员在统一的“空闲时间”区域填写周一至周四，按授权校区勾选整班空闲，不区分值班类型。参与统计的成员保存时必须至少选择一天完整空闲；通常安排持续沿用，临时变化只覆盖对应周，也可恢复沿用，但不能恢复到未填的通常安排。旧时间窗口完整覆盖固定班次时显示为有空，部分覆盖提示重新选择，读取不改写原数据。既有特殊时段和班次 ID 保留，主动替换才使用固定时段。

自动建议共同编排当前校区周一至周四的维修与办公班表，跳过暂停日。空闲填报与自动候选仅包括有效硬件部主要任职部员、有维修事务任职的部员，其他身份均显示“值班统计”和“不参与值班统计”。办公候选依据维修事务任职，维修候选依据硬件部主要任职；交流维修本身不产生候选。兼具两类资格时优先安排办公，未排到办公时进入维修安排，两类使用同一份空闲。任何有效的部长（含副）及以上任职均不参与空闲填报、自动建议、手动排班与接替；排班管理权限独立保留。候选要求有效账号和校区授权。硬件部员每周合计安排一天，未填空闲仍进入维修安排并提示冲突；比较多种维修均衡配额和匹配方案，使维修每日人数差不超过2，在此条件下最小化空闲冲突，同等冲突时优先减少缺岗和均衡人数。办公只从已填且当天在本校区整班空闲的人中安排，每天最多一人，无人可排留空并提醒，不要求所有办公候选都排到班，也不套用维修均衡要求。同样输入结果相同，不设置负责人位置。“办公班次”是工作名称。

硬件部员的每周一天要求跨校区、两类值班合计，其他校区已有班次计入占用。普通办公候选可在不同空闲日轮值，优先分散到不同成员，避免同日冲突。普通成员手动安排允许作为例外发布，需保留审计。无每日人数门槛；当天无人可排提醒缺岗，不强制补足。建议不写班表，重新生成只替换自动部分，保留普通成员的发布及手动调整内容，剔除旧负责人安排；历史数据在实际发布替换时归档。两类班表同事务发布，检查版本、权限、人员有效性和时间冲突，幂等准备每日共用签到场次，但不生成签到事实。

排班页持续核对未安排的硬件部员，显示姓名和未填空闲、其他校区或暂停日等原因；其他校区已安排的成员不作为遗漏，普通办公候选未被选中不作为遗漏。每个服务日分别检查维修和办公缺岗，办公有人不能掩盖维修无人。提示不阻止负责人按实际情况发布。

扫码签到、直接签到以及我的值班入口共用一次“确认到岗信息”，统一显示姓名、身份、校区、日期与签到窗口。对需要参与统计且下周有效空闲为空的成员，在同页提醒到“我的值班”至少选择一天，不在签到页增加填报控件，不阻止签到或维修工作。通常空闲有整班可沿用时不重复提醒；下周单独例外为空时仍提醒。签到成功直接关闭确认页并更新已签到状态，不再追加成功弹窗；网络响应丢失时核对真实签到，保持首次事实。

系统只保留双方自助调岗：原值班成员发起接替邀请，对方同意后直接更新已发布班表，无需负责人审批或重新发布。发起和同意均须在北京时间的值班日期之前完成，当天零点起禁止；涉及两班互换时，以较早的值班日期为截止。过期邀请显示已过调岗期限，不再计入待办。发起者可撤回，对方可拒绝。当前人员有效性、校区范围、班次版本和时间冲突在事务内检查。请假由成员通过 QQ 与负责人线下沟通，负责人按实际结果调整班表。系统不提供请假登记、撤销或审批，也不存储请假数据。详见 [排班接口与结构](architecture/schedule.md)。

0056迁移删除旧请假表、请假专属审计与操作回执，不保留占位；既有班次、接替邀请及真实签到不变。若保留的手动班次、任职范围或全周暂停导致优化条件无法同时满足，生成结果必须明确提示。

排班及签到提醒按周一至周日归周；预约概览、原周日历及服务日配置保留现有周日口径，以精确日期衔接，不转换教务星期值或重写历史周键。手动维修选人优先硬件部部员，其次交流维修，再次其他部员；办公优先基础事务站部员（办公室、美工部、推广部），其次其他部门。完整显示姓名、学号、校区、部门、职位及附加任职，空闲冲突、跨部门和每周重复安排保留提示及人工例外，不额外设置岗位资格白名单。

今日名单从有效班次关联真实签到，覆盖未签到人员，人数按成员去重，临时到场单列。未结束的班次显示待签到，当天最后一班结束仍未签到自动记缺勤。实际到场由本人签到记录确定，漏签由有权限人员填写原因补记。扫码并发与重试保留首次事实。

现场签到码由负责人或有效维修事务人员在授权校区出示，不要求本人先签到。维修事务人员无论是否排班，均可在原签到时段内直接到岗签到。每人刷新仅替换本人的码，其他人的码继续有效。今日工作和个人中心顶部按服务端权限及当前校区、日期的真实考勤记录显示签到待办，签到成功后立即隐藏；我的值班复用相同规则。维修部员通过专用入口扫码签到，现有办公排班人员及负责人直接签到规则保留。工作人员只需签到一次，无需手动离岗或返回岗位。缺勤由已结束班次与真实签到自动判断，不提供人工确认未到或撤销入口。漏签补录与时间修正从人员行进入，服务端按人员、日期、校区解析场次，并要求填写原因。历史补录不改变到场事件，暂停服务、越权和失效人员在提交事务内拒绝。签到和接单解耦。签到来源保存扫码签发人、直接签到或补记操作者，重复签到不覆盖首次来源，仅考勤管理范围内可见；未记录来源的历史数据不推断补填。

漏签补录以值班页所选日期和校区为准，不另选日期或时间；服务端采用本人当天在该校区最早班次的开始时间，无排班采用默认 19:00，标记为按班次开始时间补记并单独保存操作时间。已有签到的时间修正只选择当日时分，日期固定原记录所属值班日期，前后端均不允许跨日修正；版本、原因和审计继续保留。

周报的实际次数、首次有效签到、负责人每周一次，月报的计数模式、小时换算和负责人合并继续沿用现有参数，个人时长与管理报表共用计算逻辑，先过滤访问范围再聚合。默认核算时长不生成虚假签到，维修数量和持续时间不作为出勤或志愿时长依据。暂停服务保留原业务事实，按原算法从有效服务日核算中排除。不新增4/16小时制度、月度封顶、结转或学期清零。

接收、接单、交接、结束和修改自动记录操作者与实际操作时间，字段修改保留前后值。原始预约、维修、照片、签到、人员和审计历史持续保留；历史未修复不能推断为部分解决或未解决，也不能补造历史协助或到岗事实。
